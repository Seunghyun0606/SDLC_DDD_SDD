# 탄력근로제 개선 최초근무계획 자동 설정 — 고객 기능 설계 협의서

## 문서 목적
현재 요구사항에서 합의 가능한 사용자 관점의 기능 흐름과 아직 결정되지 않은 업무 정책을 구분해 고객과 검토한다.

## 한눈에 보기
사용자는 탄력근로제 근무계획을 조회·저장할 수 있고, 조건이 충족되면 기본 근무스케줄을 이용해 최초 계획을 생성할 수 있는 방향으로 설계한다. 단, 자동 생성 조건과 기존 계획 처리 정책은 고객 확인 전까지 확정하지 않는다.

## 개선 후 사용 흐름
1. 사용자가 대상자의 근무계획을 조회한다.
2. 최초 계획이 필요한 상황이면 시스템이 기본 근무스케줄을 조회한다.
3. 시스템이 생성 가능한 근무계획 후보를 만든다.
4. 업무 검증 조건을 통과한 경우 계획을 저장한다.
5. 사용자는 생성·저장 결과를 확인한다.

## 주요 입력과 결과
- 대상자/대상 기간: 고객 정책 확인 필요
- 기본 근무스케줄: 기준정보 위치 및 우선순위 확인 필요
- 결과: 생성된 근무계획과 저장 결과

## 업무 규칙과 예외
- 기존 근무계획 존재 시 처리: `OPEN`
- 자동 생성 실행 시점: `OPEN`
- 권한 및 대상자 범위: `OPEN`
- 부분 실패/중복 실행 정책: `OPEN`

## 고객과 함께 확인할 내용
위 `OPEN` 항목을 확정해야 프로그램 상세 설계의 입력 DTO, 저장 규칙, 트랜잭션, 동시성/중복 처리까지 구현 수준으로 확정할 수 있다.

## 합의된 내용
저장/조회/기본 스케줄 기반 자동 생성 기능의 필요성은 원본 요구사항으로 확인된다.

## 미확정 사항
실제 화면/API/테이블/프로그램명은 실제 프로젝트 Source가 연결되기 전까지 고객 본문에 확정값으로 표시하지 않는다.
