# 프로젝트 설정 가이드

이 문서는 `START_HERE.md`의 setup 단계를 조금 더 자세히 설명합니다. 일반 프로젝트 참여자가 내부 Config 파일 구조를 직접 해석하지 않아도 되는 것을 목표로 합니다.

처음이라면 먼저 [START_HERE](./START_HERE.md)를 읽으세요.

## 1. 가장 먼저 실행할 명령

```bash
python sdlc/scripts/harness.py setup \
  --name <project-name> \
  --mode AUTO \
  --delivery STANDARD
```

사용자가 처음 선택할 핵심 값은 세 가지입니다.

| 항목 | 무엇을 넣나 | 모르면 |
|---|---|---|
| 프로젝트명 | 팀이 알아볼 수 있는 이름 | 임시 이름 사용 가능 |
| 프로젝트 유형 | `GREENFIELD`, `BROWNFIELD`, `HYBRID`, `AUTO` | `AUTO` |
| 진행 수준 | `FAST`, `STANDARD`, `FULL` | `STANDARD` |

나머지 기술 정보는 확인 가능한 Repository 자산에서 먼저 탐색하고, 확인할 수 없으면 미확정으로 남기는 것이 기본입니다.

## 2. 프로젝트 유형

### GREENFIELD

기존 Source가 없거나 신규 시스템을 만드는 경우입니다. Source가 없는 것은 오류가 아닙니다.

Agent는 제공 자료를 바탕으로 요구사항/기능/인수조건과 설계 후보를 작성할 수 있지만, 고객 정책이나 권한을 임의 확정하면 안 됩니다.

### BROWNFIELD

기존 운영 Source가 있는 변경·고도화 프로젝트입니다. Repository, Build/Test, DB, Interface 등의 실제 근거를 먼저 확인합니다.

찾지 못한 영역은 `영향 없음`이 아니라 Coverage Gap으로 남겨야 합니다.

### HYBRID

기존 시스템 변경과 신규 기능 영역이 함께 있는 경우입니다.

### AUTO

잘 모르겠다면 이 값을 사용합니다. Harness는 일반적인 Source/build/schema 자산을 보고 후보 Mode를 정합니다. Git Repository가 있다는 이유만으로 Brownfield라고 확정하지 않습니다.

## 3. 진행 수준

### FAST

작은 운영 변경이나 저위험 변경에 사용합니다. 최종적으로 문서 수 자체도 줄이는 개선은 WP-11에서 별도로 진행합니다.

### STANDARD

일반 SI/SM 기능의 기본값입니다.

### FULL

대형·고위험 범위나 더 강한 추적성이 필요한 경우 사용합니다.

처음부터 모든 프로젝트를 FULL로 시작하지 않습니다.

## 4. setup이 자동으로 확인하는 것

현재 Runtime은 Repository에서 다음과 같은 신호를 탐색합니다.

- Java/Maven/Gradle
- JavaScript/TypeScript package
- Python project 신호
- 일반적인 Source/Test/Resource root
- Spring/MyBatis/JPA/Kafka 일부 신호
- Schema/DDL 파일
- Build/Test command 후보

탐색 결과는 **확인 가능한 기술 후보**입니다. Source에 구현되어 있다는 이유만으로 업무정책으로 승격하지 않습니다.

## 5. Agent Provider 연결

실제 Agent가 문서를 생성하려면 Provider 연결이 필요합니다.

Provider wrapper가 준비되어 있다면 setup 때 command를 전달할 수 있습니다.

```bash
python sdlc/scripts/harness.py setup \
  --name <project-name> \
  --mode AUTO \
  --delivery STANDARD \
  --provider-command '<agent-command> --context {context_path} --result {result_path}'
```

Provider가 아직 없으면 setup 결과가 `CONFIGURED_PROVIDER_REQUIRED`가 될 수 있습니다. 이것은 “설정 파일 생성 실패”가 아니라 **Agent 실행 준비가 아직 끝나지 않았다**는 뜻입니다.

사용자에게 Provider의 내부 result schema를 직접 작성하게 하지 않습니다. Provider Adapter 자체의 공식 Reference 제공은 WP-09 범위입니다.

## 6. setup 후 확인

```bash
python sdlc/scripts/harness.py check --setup
```

일반 사용자는 다음만 확인하면 됩니다.

- 프로젝트 유형이 의도와 맞는가
- 진행 수준이 맞는가
- Brownfield라면 Source root가 실제 분석 대상과 맞는가
- Build/Test 후보가 있다면 실제 프로젝트 명령과 맞는가
- Agent Provider가 연결되었는가
- 확인이 필요한 항목이 무엇인가

내부 Config 이름이나 Canonical 저장 구조를 이해하는 것은 일반 사용자의 setup 완료 조건이 아닙니다.

## 7. 자료를 추가할 때의 원칙

자료는 가능한 한 원본 형태를 보존합니다.

- 요구사항 Excel을 Markdown으로 다시 옮겨 적지 않습니다.
- 기존 설계서가 있으면 원본을 보존합니다.
- Source/DB/Interface 자료에는 기준 Branch/Commit/Version을 알 수 있으면 함께 기록합니다.
- 업무정책과 Source 관찰 결과를 섞지 않습니다.
- 읽을 수 없는 PDF/이미지라면 내용이 없다고 판단하지 말고 별도 추출/OCR 필요로 남깁니다.

표준 사용자 Workspace의 자동 생성과 `docs/**` / `.sdlc/**` 완전 분리는 WP-04에서 수행합니다.

## 8. 사람이 확인해야 하는 setup 결정

Agent가 자동 탐색할 수 없는 것 중 실제 결정권한이 필요한 것만 사람에게 확인합니다.

- 이 프로젝트의 업무 범위
- 고객에게 공유할 산출물 수준
- Architecture/기술 선택의 승인
- 보안·개인정보·운영 제약
- Git 운영 정책과 Source write 허용 범위
- 기존 시스템에서 분석 제외할 범위

반대로 아래는 가능한 경우 Agent/Runtime이 먼저 조사해야 합니다.

- Source root 후보
- build file
- test root
- Framework 사용 흔적
- Mapper/Repository 후보
- DB/Interface 관련 파일 후보

## 9. 자주 보는 상태

| 상태 | 의미 | 사용자 행동 |
|---|---|---|
| `CONFIGURED_PROVIDER_REQUIRED` | 기본 setup은 됐지만 실제 Agent Provider가 없음 | Provider 연결 또는 프로젝트 관리자 확인 |
| `SETUP_OR_PROVIDER_REQUIRED` | setup/check 관점에서 아직 실행 준비가 안 됨 | `check --setup` 결과의 확인 필요 항목 확인 |
| `READY_FOR_PLAN` | Provider와 기본 구조가 있어 계획 실행 가능 | RQ Target이 있다면 `work --plan-only` |
| `HARNESS_VALIDATION_FAILED` | Runtime 구조 검사가 실패 | 실패 메시지 기준으로 관리자 확인 |

`READY_FOR_PLAN`도 “설계/개발 완료” 또는 “Production Ready”를 의미하지 않습니다.

## 10. 첫 요구사항 연결의 현재 한계

현재 `setup` 이후 빈 프로젝트에서 바로 `RQ-001`을 생성하는 통합 명령은 없습니다.

XLSX 요구사항 후보 추출은 가능합니다.

```bash
python sdlc/scripts/import_requirements.py <requirements.xlsx>
```

하지만 현재 importer는 후보 JSON/리포트 생성까지이며, Canonical RQ 등록과 첫 Target 반환이 자동 연결되어 있지 않습니다.

따라서 신규 사용자가 내부 저장 파일을 수동 수정해서 이 단절을 우회하지 않도록 합니다. 이 문제는 Session 3 / WP-03의 `harness.py intake`에서 해결해야 합니다.

## 11. 다음 단계

setup이 끝났다면 [START_HERE](./START_HERE.md)의 “요구사항 또는 변경요청을 등록한다”로 돌아갑니다.

현재 RQ가 이미 있다면:

```bash
python sdlc/scripts/harness.py check --target <RQ-ID>
python sdlc/scripts/harness.py work --target <RQ-ID> --plan-only
```

첫 RQ가 아직 없다면 WP-03 연결 전까지는 setup과 원본 자료 준비 상태에서 멈추는 것이 내부 Canonical을 사람이 수동 편집하는 것보다 안전합니다.
