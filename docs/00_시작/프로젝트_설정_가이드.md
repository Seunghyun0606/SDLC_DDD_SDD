# 프로젝트 설정 가이드

일반 프로젝트 참여자가 직접 유지하는 설정 Source of Truth는 `.sdlc/project.yaml` 하나입니다.

## 기본 실행

```bash
python sdlc/scripts/harness.py setup \
  --name <project-name> \
  --mode AUTO \
  --delivery STANDARD

python sdlc/scripts/harness.py check --setup
```

`setup`은 Repository에서 확인 가능한 Source root, Build/Test, Language/Framework/DB 후보를 먼저 탐색합니다. 확인하지 못한 값은 `unresolved`로 남깁니다.

기본 Agent 실행모드는 `INTERACTIVE`입니다. 따라서 Cursor, Codex, Claude Code 또는 다른 Repository-capable IDE/CLI Agent에서 Harness를 사용한다면 별도의 Provider 설정이 필요하지 않습니다.

## Agent 실행 방식

Agent 제품명과 프로젝트 업무 설정을 분리합니다. 같은 Repository를 어떤 사용자는 Cursor로, 다른 사용자는 Codex/Claude Code로 작업할 수 있으므로 `host: CURSOR` 같은 값을 Project Config에 고정하지 않습니다.

### 기본: INTERACTIVE

`agent` 항목을 생략하면 다음과 같습니다.

```yaml
agent:
  execution: INTERACTIVE
```

의미:

- 현재 대화/IDE/CLI 세션을 수행 중인 Agent가 Stage Agent입니다.
- Harness가 별도 LLM/Agent subprocess를 다시 실행하지 않습니다.
- `/work`는 Work Context를 준비하고 `INTERACTIVE_HANDOFF_READY`를 반환합니다.
- 현재 Agent가 Artifact와 `stage-result.json`을 작성한 뒤 finalize를 실행합니다.
- Stage Result Validator와 Canonical Guard를 통과한 경우에만 완료입니다.

예:

```bash
python sdlc/scripts/harness.py work --target RQ-001
```

Agent는 반환된 `context_path`와 `sdlc/agent/skills/work/SKILL.md`를 읽고 작업한 뒤 반환된 finalize command를 실행합니다.

### 선택: HEADLESS

CI/Batch/자동 Agent 호출처럼 Harness가 외부 Agent를 직접 실행해야 하는 프로젝트에서만 설정합니다.

```yaml
agent:
  execution: HEADLESS
  provider:
    id: PROJECT_AGENT_PROVIDER
    timeout_seconds: 180
    command:
      - python
      - path/to/provider_adapter.py
      - --context
      - "{context_path}"
      - --result
      - "{result_path}"
```

`HEADLESS`인데 `agent.provider.command`가 없으면 Config 오류로 처리합니다.

기존 `sdlc/config/agent-provider.json`과 `--provider-command`는 기존 자동화 프로젝트의 호환 경로로만 유지합니다. 신규 프로젝트의 사용자 설정으로 권장하지 않습니다.

## 사람이 직접 관리하지 않는 파일

다음은 Runtime/Legacy compatibility용 Machine artifact입니다.

```text
.sdlc/runtime/effective/project-profile.json
.sdlc/runtime/effective/source-profile.json
.sdlc/runtime/effective/agent-execution.json
.sdlc/runtime/effective/agent-provider.json
.sdlc/runtime/effective/project-context.json
.sdlc/runtime/effective/config-usage.json
sdlc/config/project-profile.yaml
sdlc/config/source-profile.yaml
sdlc/config/agent-provider.json   # Legacy compatibility
```

새 프로젝트에서 위 파일을 여러 개 나눠 수정해서 설정을 바꾸지 않습니다.

## `.sdlc/project.yaml`에 넣는 내용

확인된 값만 유지합니다.

- 프로젝트명 / Mode
- FAST / STANDARD / FULL
- Language / Framework
- Source/Test/Resource root
- Build/Test command
- Git 보호 Branch
- Architecture/Data/Interface/Security 등 확인된 프로젝트 Context
- 필요한 경우에만 Agent execution (`INTERACTIVE / HEADLESS`)
- 아직 확인이 필요한 `unresolved`

완성 예시는 `sdlc/config/project.example.yaml`을 참고합니다. 예시 값을 프로젝트 사실처럼 복사하지 않습니다.

## Config 소비 원칙

각 key는 다음 중 하나여야 합니다.

- Runtime 소비
- Extension 소비
- Agent/문서 Project Context
- Dead Config

Dead Config와 잘못된 schema/mode/delivery/agent execution은 조용히 무시하지 않고 실패합니다.

Project Context는 보관만 하지 않고 `work/change` Agent plan에 포함됩니다. INTERACTIVE에서는 현재 Agent가 Work Context로 읽고, HEADLESS에서는 Provider의 `{context_path}`로 전달됩니다.

## setup 다음 단계

```bash
python sdlc/scripts/harness.py intake <requirement-file.xlsx>
```

표준 요구사항 XLSX는 별도 Column Profile 없이 인입합니다. 인입 결과가 실제 `RQ-001` 같은 Target을 반환하면 해당 Target으로 `work`를 진행합니다.

Interactive Agent에서는 보통 다음처럼 바로 실행합니다.

```text
/work --target RQ-001
```

또는 Host가 Slash Command를 지원하지 않으면 다음처럼 자연어로 요청할 수 있습니다.

```text
RQ-001 다음 단계 작업해줘
```

Host Adapter가 Core Skill `sdlc/agent/skills/work/SKILL.md`로 연결해야 합니다.

## 사람에게 확인할 항목

Runtime이 Source/Repository에서 확인할 수 있는 내용을 먼저 조사합니다. 사람에게는 업무정책·범위·승인·권한·기술 선택처럼 실제 판단권한이 필요한 항목과 남은 OPEN만 요청합니다.

## Validation 경계

`INTERACTIVE_HANDOFF_READY`와 `PLAN_READY`는 완료가 아닙니다. Artifact와 Stage Result를 만든 뒤 동일한 Validator/Target Graph/Business Truth/Canonical Guard를 통과해야 합니다.

Config/Runtime/Behavioral Test가 성공해도 각 Host Agent가 Core Skill을 실제로 발견·준수하는지는 Cursor/Codex/Claude Code 등 Cross-Agent Pilot에서 별도로 검증합니다.
