# RQ 작업목록 운영 가이드

이 문서는 PM과 이해관계자가 Requirement Intake 또는 `rq-add` 이후 RQ를 배정하고, 현재 진행상태와 다음 작업을 관리하는 방법을 설명한다.

## 1. PM은 Excel/CSV를 기본 화면으로 사용한다

프로그래밍 명령에 익숙하지 않은 PM은 다음 흐름을 권장한다.

```text
RQ 생성
→ PM용 Excel Export
→ 담당자/일정/WBS/메모 편집
→ Import
→ RQ 작업목록 자동 합성
```

PM 파일은 프로젝트 관리정보이고 요구사항/업무규칙 자체를 변경하지 않는다.

## 2. 최초 PM 파일 만들기

Requirement Intake 또는 `rq-add` 후:

```bash
python sdlc/scripts/harness.py rq-list export \
  --format xlsx \
  --output docs/00_관리/RQ_작업관리.xlsx
```

CSV도 지원한다.

```bash
python sdlc/scripts/harness.py rq-list export \
  --format csv \
  --output docs/00_관리/RQ_작업관리.csv
```

Cursor에서는 `/rq-list`, 다른 Agent에서는 `sdlc/agent/skills/rq-list/SKILL.md`의 같은 규칙을 사용한다.

자연어 예:

```text
PM용 RQ 관리 엑셀 만들어줘.
RQ 작업목록 최신 상태로 보여줘.
수정한 RQ_작업관리.xlsx를 반영해줘.
```

## 3. 기본 식별 컬럼

| 컬럼 | 수정 여부 | 의미 |
|---|---|---|
| RQ | 수정 금지 | Harness RQ ID |
| 요구사항명 | 조회용 | 현재 요구사항명 |
| 외부 요구ID | 조회용 | 고객 원본 요구 ID |

이 뒤에는 PM이 프로젝트에 필요한 컬럼을 자유롭게 추가할 수 있다.

예:

```text
RQ | 요구사항명 | 외부 요구ID | 담당개발자 | 업무담당 | QA | 우선순위 | Sprint | 목표배포일 | WBS | PM메모
```

다른 프로젝트는 전혀 다른 PM 컬럼을 사용해도 된다.

## 4. PM 파일 반영

```bash
python sdlc/scripts/harness.py rq-list import \
  docs/00_관리/RQ_작업관리.xlsx
```

Import 후 대표적으로 다음이 갱신된다.

```text
.sdlc/management/rq-planning.json
sdlc/runtime/management/rq-worklist.json
docs/00_관리/RQ_작업목록.md
```

기본 Import는 현재 파일의 PM 컬럼 구성을 PM 관리 Schema로 사용한다.

- 컬럼 추가 → PM 컬럼 추가
- 컬럼 삭제 → 해당 PM 컬럼 제거
- 셀 비움 → 해당 값 비움

일부 컬럼만 합치고 기존 PM 컬럼을 보존하려면:

```bash
python sdlc/scripts/harness.py rq-list import 일부수정.csv --merge-columns
```

## 5. PM 정보와 자동 상태를 섞지 않는다

PM이 직접 관리하는 값:

```text
담당자 / 일정 / WBS / 우선순위 / 메모 / 회의용 컬럼
```

Harness가 실제 작업 근거에서 계산하는 값:

```text
현재 작업상태 / Change Level / 확인 필요사항 / 검증근거 / 생성문서 상태 / 다음 작업
```

PM Excel에서 상태 문구를 바꿨다고 Runtime 작업이 완료되지는 않는다.

PM이 자동 상태와 같은 이름의 Custom 컬럼을 만들면 Generated View에서 PM 값임을 구분해 표시한다.

## 6. 새 RQ가 생겼을 때

### 프로젝트 중 소수 신규 요구

```bash
python sdlc/scripts/harness.py rq-add \
  --title "승인 후 수정 제한" \
  --request "승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘."
```

상세: `17_RQ_간편추가_가이드.md`

### 대량/파일 기반 신규 요구

```bash
python sdlc/scripts/harness.py intake 추가요구사항.xlsx
```

새 RQ가 만들어지면 작업목록을 다시 합성할 수 있다.

```bash
python sdlc/scripts/harness.py rq-list refresh
```

다음 Export에는 새 RQ도 포함된다.

## 7. 새 RQ를 PM Excel에서 직접 만들지 않는다

PM Excel에 임의의 `RQ-999` 행을 추가해서 새 요구사항을 만드는 방식은 지원하지 않는다.

```text
한두 건 신규 요구 → rq-add
대량/파일 신규 요구 → intake
기존 RQ 업무 의미 변경 → /change
```

기존 RQ의 취소·범위변경도 PM 행 삭제로 처리하지 않고 업무 의미 변경 흐름에서 처리한다.

## 8. 현재 상태 확인

전체 목록 갱신:

```bash
python sdlc/scripts/harness.py rq-list refresh
```

특정 RQ:

```bash
python sdlc/scripts/harness.py check RQ-001
```

프로젝트 전체:

```bash
python sdlc/scripts/harness.py check project
```

사람용 상태는 대략 다음 흐름으로 표현된다.

```text
작업 준비
→ 사람 결정 대기 (필요한 경우)
→ 개발·검증 진행
→ 고객 인수 대기
→ 배포 대기
→ 배포완료·실제 구현결과 확인 대기
→ 완료·현행화
```

근거 없는 임의 진척률보다 실제 Build/Test/검증/인수/배포 근거와 다음 작업을 우선한다.

## 9. RQ와 참고문서

RQ 분석 전에 어떤 규정·회의록·업무문서를 참고할지 관리하려면 `13_RQ_참고문서_레지스트리_가이드.md`를 사용한다.

참고문서 연결은 PM 정보와 마찬가지로 업무 사실 자체를 자동 변경하지 않는다.

## 10. 기존 단일 CLI 배정 방식

기존 자동화나 고급 사용자를 위해 단일 RQ 배정 명령도 유지한다.

```bash
python sdlc/scripts/harness.py rq-list assign \
  --target RQ-001 \
  --engineering-owner "박개발" \
  --test-owner "최QA" \
  --priority HIGH
```

일반 PM에게는 Excel/CSV 방식을 권장한다.

## 11. 하지 말아야 할 것

- PM Excel에서 새 RQ ID를 임의 생성하지 않는다.
- PM 값으로 Requirement/Business Rule을 변경했다고 간주하지 않는다.
- 자동 상태를 PM이 수동으로 완료 처리하지 않는다.
- 기존 RQ의 정책 변경을 PM 메모로만 끝내지 않는다.
- Framework 관리용 작업목록을 프로젝트 RQ 목록으로 재사용하지 않는다.
