# 요구사항 정의 완성 예시 — REQ_TM_FL001

> 이 문서는 빈 Template 작성 예시가 아니라, 실제 제공된 요구사항 Evidence에서 Agent가 어디까지 작성하고 어디부터 OPEN으로 남겨야 하는지를 보여주는 완성 예시입니다.

## 문서 목적

제공된 요구사항 원문을 훼손하지 않고 요구사항 정의 초안을 만들며, 근거가 없는 업무정책·범위·승인 조건을 발명하지 않습니다.

## 한눈에 보기

| 항목 | 내용 | 근거 상태 |
|---|---|---|
| 외부 요구사항 ID | REQ_TM_FL001 | GIVEN |
| 요구사항 그룹 | 탄력근로제 개선 최초근무계획 자동 설정하는 기능 | GIVEN |
| 요구사항 원문 | 탄력근로제 근무계획 저장 | GIVEN |
| 기존 Source Repository | 제공되지 않음 | GIVEN |
| 현재 문제 | OPEN | 근거 부족 |
| 기대 결과 상세 | OPEN | 근거 부족 |
| 업무 규칙 | OPEN | 근거 부족 |

## 업무 흐름

현재 Evidence에서 확인되는 범위는 **탄력근로제의 근무계획 저장 기능이 요구되었다**는 점입니다.

저장 전 승인 절차, 저장 단위, 자동 생성 조건, 수정 가능 시점, 예외 처리 방식은 제공 Evidence만으로 확인되지 않으므로 업무 흐름으로 확정하지 않습니다.

## 입력 및 근거

- Source Document: `요구사항목록.xlsx`
- External Requirement ID: `REQ_TM_FL001`
- Requirement Group: `탄력근로제 개선 최초근무계획 자동 설정하는 기능`
- Requirement Text: `탄력근로제 근무계획 저장`
- Evidence Class: `GIVEN`
- 기존 Source Repository: 없음

## 상세 내용

### 요구사항 정의

탄력근로제 근무계획을 저장할 수 있어야 한다.

이 문장은 원문을 테스트 가능한 기능 후보로 정리한 **Agent 초안(CANDIDATE/INFERRED)** 이며, 원문 자체를 대체하거나 Business Truth로 자동 확정하지 않습니다.

### 기능 요구 후보

| 후보 | 내용 | 상태 |
|---|---|---|
| FR 후보 1 | 시스템은 탄력근로제 근무계획 저장 기능을 제공한다. | CANDIDATE / INFERRED |

### 인수 조건 후보

현재 Evidence에는 저장 성공의 구체 기준이 없습니다. 따라서 임의의 시간·상태·승인 조건을 추가하지 않고 다음과 같이 최소 후보만 둡니다.

- 저장 기능이 실제 프로젝트 요구 범위에 포함되는지 확인할 수 있어야 한다. `OPEN`
- 저장 대상 데이터와 성공 판정 기준은 추가 Evidence 또는 권한 있는 결정이 확보될 때 구체화한다. `OPEN`

## 미확정 사항·주의·가정

### Agent가 추가 Evidence를 찾아야 하는 OPEN

- 실제 저장 대상 필드
- 기존 시스템에 동일/유사 기능이 있는지 여부
- 저장 API, Table, Program 존재 여부
- 오류/예외 처리 방식

Brownfield Source가 제공되면 Agent가 조사할 항목이며, 사람이 처음부터 작성할 항목으로 돌리지 않습니다.

### 사람이 결정해야 할 수 있는 항목

다음 항목은 Evidence 조사로 확정할 수 없고 실제 프로젝트 판단권한이 필요한 경우에만 Human Review로 올립니다.

- 업무 정책: 근무계획 저장 전 승인 규칙
- 범위: 어떤 조직/근무유형을 적용 대상으로 할지
- 승인: 누가 업무 규칙을 최종 승인하는지
- 기술 선택: 프로젝트가 선택해야 하는 구현 방식이 실제로 존재할 경우

현재 제공 Evidence만으로는 이 값들을 확정할 수 없으므로 모두 `OPEN`입니다.

## 관련 ID 및 추적성

- External Requirement: `REQ_TM_FL001`
- Source: `요구사항목록.xlsx`
- Canonical RQ/FR ID는 실제 Intake Runtime이 부여하며 이 예시에서 임의로 고정하지 않습니다.

## 다음 작업

1. 실제 Intake로 생성된 RQ Target을 선택합니다.
2. `python sdlc/scripts/harness.py work --target <실제-RQ-ID>`를 실행합니다.
3. Agent가 Evidence 기반 문서를 생성합니다.
4. Runtime이 Human authority 항목을 명시한 경우에만 `review`로 답변합니다.
5. 결과의 `next_command`로 다음 단계에 진행합니다.

이 예시는 `REQ_TM_FL001`의 제공 Evidence 범위를 넘어 업무정책이나 기술 사실을 발명하지 않습니다.
