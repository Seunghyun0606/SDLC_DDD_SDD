# 이해관계자별 작업 가이드

이 문서는 **누가 무엇을 보고 무엇을 결정하는지** 역할별로 설명한다. Template 구조는 `04_TEMPLATE_및_산출물_가이드.md`, Config는 `02_PROJECT_설정가이드.md`를 본다.

## 1. 공통 원칙

프로젝트 참여자는 빈 Template을 처음부터 채우는 사람이 아니다.

```text
Agent가 요구사항·기존 문서·Source·DB·Config를 먼저 조사
→ 확인 가능한 내용으로 초안 작성
→ 사람이 결정해야 하는 내용만 질문
→ 사람이 답변하거나 나중에 확인하도록 보류
→ 생성 문서 검토
```

Source에서 확인 가능한 Class/Method/Query/Table/파일경로 등을 사람이 다시 찾아 입력하는 것을 기본 절차로 하지 않는다.

## 2. PM

### 주로 본다

- `docs/00_관리/RQ_작업목록.md`
- PM용 `RQ_작업관리.xlsx` 또는 CSV
- `python sdlc/scripts/harness.py check project`
- 특정 RQ의 현재 상태와 다음 작업
- 담당자/일정/WBS/우선순위
- 사람 판단이 필요한 건

### 결정한다

- 프로젝트 범위와 우선순위
- 일정/배정
- 고객 의사결정 경로
- Release/Milestone 운영 기준

### 사용한다

```text
/rq-list
/check
```

새 RQ 소수 추가가 필요하면 `/rq-add`, 대량 요구사항 파일은 `intake`를 사용한다.

### 하지 않는다

- 기준 정보 JSON 직접 편집
- 상태를 PM Excel에서 임의로 완료 처리
- 모든 산출물 Template을 직접 작성

상세: `12_RQ_작업목록_운영가이드.md`

## 3. 업무 분석가 / BA

### 주로 본다

- 원본 요구사항과 RQ 생성 근거
- Work Map / Work Unit SDD의 업무 부분
- 고객 합의 문서
- 아직 업무 판단이 필요한 사항
- RQ에 연결된 고객 규정·회의록·업무문서

### 결정한다

- 업무 목적
- 업무 규칙과 예외
- 적용 대상/범위
- 용어 의미
- 목표 업무 동작

### 요청 예

```text
RQ-0042의 월 마감 정책은 급여 마감 전까지만 재계산을 허용하도록 바꿔줘.
```

기존 업무 의미가 바뀌는 요청은 `/change` 흐름으로 반영한다.

### 하지 않는다

- Source의 현재 동작을 곧바로 고객 업무정책으로 확정
- Java/JSP/XML 정보를 처음부터 문서에 수기 입력

## 4. 설계자

### 주로 본다

- Work Map
- Work Unit SDD
- 필요한 Program Spec
- 현재 Source/DB/Interface 근거
- 인수·테스트 기준
- 영향 범위

### 검토한다

- 기능 흐름
- 상태/예외 처리
- 데이터 의미
- 권한
- Interface/Transaction 요구
- 구현 전에 추가 확인이 필요한 설계사항

### 사용 구분

```text
Source/DB/설계/Program Mapping 보완 → /work
업무 의미/범위/정책 변경             → /change
```

### 하지 않는다

- Agent가 Source에서 확인할 수 있는 Mapping을 처음부터 수동 작성

## 5. 개발자

### 주로 본다

- Work Unit SDD
- 필요한 Program Spec
- 관련 Source/Trace
- 프로젝트 개발표준과 Rule
- 개발 전에 확인해야 하는 미확정 사항
- Build/Test 결과

### 수행한다

- 허용 Source root 안에서 실제 구현
- `/work`를 통한 Source/Program Mapping 보완
- Build/Test 실행
- 실제 구현 결과 반영

### 보고한다

- 예상하지 못한 Legacy 영향
- Source와 설계의 불일치
- Build/Test 실패
- 더 큰 영향 범위가 발견된 경우

예상보다 영향이 커지면 Change Level이 상향될 수 있다.

프로젝트 개발가이드 적용은 `16_프로젝트_개발가이드_Agent_적용가이드.md`를 본다.

## 6. 테스트 담당자

### 주로 본다

- 요구/기능의 인수 조건
- Work Unit SDD의 테스트 연결
- 고객용 테스트·인수 문서
- 실제 Build/Test/검증 근거

### 수행한다

- 테스트 시나리오 검토
- 테스트 결과 확인
- Coverage Gap 보고
- 업무 합격 기준이 불명확하면 업무 담당자와 확인

### 하지 않는다

- 테스트 문서를 무조건 처음부터 수기로 작성
- 실제 결과가 없는데 PASS로 표시

## 7. 프로젝트 아키텍트

### 집중 확인한다

- Cross-domain 영향
- Interface/Batch
- Schema/Transaction
- Security/Privacy
- Architecture boundary 변경
- 프로젝트 규칙 예외
- L4/L5 고위험 변경

Agent가 현재 구조를 먼저 조사하고, 아키텍트는 대안 선택과 예외 승인에 집중한다.

## 8. 고객 업무담당자

### 주로 본다

- Customer Profile에서 생성한 고객문서
- 자신이 결정해야 하는 업무정책/범위/인수사항

### 결정한다

- 고객 업무정책
- 업무 범위
- 합의·인수 기준

### 주의한다

고객문서를 직접 수정했다고 프로젝트 기준 정보가 자동 변경되지는 않는다. 업무 의미가 실제로 바뀌었다면 해당 내용을 Agent에게 알려 `/change`로 반영한다.

고객에게 Engineering Template이나 Source Mapping 표를 작성하도록 요구하지 않는다.

상세: `15_고객문서_미리보기_가이드.md`

## 9. Harness 관리자 / Framework 관리자

### 프로젝트 Harness 관리자

주로 다음을 관리한다.

- `.sdlc/project.yaml`
- Project Custom Profile/Template
- 프로젝트 개발표준과 Rule
- Optional Extension 포함 여부
- Agent Host Adapter

### Framework 관리자

주로 다음을 관리한다.

- Core Runtime/Contract
- Project Scaffold 배포 구성
- Framework Test/CI
- Legacy Compatibility package

Framework 관리 도구를 실제 배포 프로젝트의 일반 사용자 명령과 섞지 않는다.

## 10. 질문에 지금 답할 수 없을 때

사용자는 모르는 값을 추측해서 답할 필요가 없다.

예:

```text
이건 고객 확인이 필요해. 설계 확정 전에 다시 확인해줘.
```

```text
DBA 확인 전이라 아직 결정 못해. Source 수정 전에 다시 확인해줘.
```

Agent는 임의 확정하지 않고 나중에 다시 확인해야 할 항목으로 유지한다. 사람에게는 내부 상태 코드보다 **무엇을, 누가, 언제 확인해야 하는지**가 보이도록 한다.

## 11. 생성 문서를 수정하고 싶을 때

오탈자 외에는 파일 자체를 바로 고치기보다 문서와 의미를 지정해 Agent에게 요청한다.

```text
HRIS 작업지시서의 저장 권한 처리 부분만 현재 Source 기준으로 다시 검토해줘.
```

```text
RQ-0042 Work Unit SDD의 업무규칙 중 마감 정책을 수정해줘.
```

Agent가 다음처럼 구분한다.

| 요청 | 흐름 |
|---|---|
| 업무 의미/정책/범위 변경 | `/change` |
| Source/DB/Mapping/구현 결과 재분석 | `/work` |
| 오탈자/표현/레이아웃 | 문서만 수정 |

## 12. 역할별 최소 문서

모든 사람이 모든 문서를 읽을 필요는 없다.

| 역할 | 우선 확인 |
|---|---|
| PM | RQ 작업목록, `/check` |
| BA | 요구사항, Work Unit SDD 업무부분, 고객 합의 문서 |
| 설계자 | Work Map, Work Unit SDD, Program Spec |
| 개발자 | Work Unit SDD, Program Spec, 프로젝트 개발가이드 |
| Tester | 인수조건, Test/Verification 결과 |
| 고객 | Customer Projection |
| Harness 관리자 | Config/Profile/Rule/Extension |
