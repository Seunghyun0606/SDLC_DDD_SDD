# 한글 인코딩 및 외부 명령 실행 가이드

## 1. 목적

프로젝트 자료와 Build/Test/정적분석/DB 도구 출력에서 한글이 깨지지 않도록 현재 Harness의 처리 기준을 설명한다.

사람이 별도로 Python `encoding` 옵션을 맞춰가며 실행하는 것이 기본 사용법은 아니다. Harness가 지원 경계에서 안전하게 처리하고, 안전하게 읽지 못한 내용은 정상 근거로 사용하지 않는다.

## 2. MD/TXT/CSV 입력자료

텍스트 자료는 손실 없는 strict decoding만 허용한다.

기본 순서:

```text
BOM 확인
→ UTF-8 strict
→ CP949 strict
→ EUC-KR strict
→ 안전하게 읽지 못하면 추출 필요로 표시
```

UTF-16 BOM이 있는 TXT도 지원한다.

중요한 원칙:

- 깨진 글자를 `�`로 바꾸고 정상 자료처럼 계속 진행하지 않는다.
- 실제로 사용한 인코딩을 추출 결과에 기록한다.
- 안전하게 읽지 못하면 해당 텍스트를 업무 판단 근거로 사용하지 않는다.

## 3. XLSX/PPTX/DOCX

Office 문서는 일반 텍스트 파일처럼 OS 기본 인코딩으로 열지 않는다.

```text
XLSX/PPTX/DOCX
→ ZIP 패키지 내부 OOXML bytes
→ XML Parser
```

따라서 일반적인 한글 Office 문서는 Windows CP949/UTF-8 console 설정과 분리해서 읽는다.

## 4. Build/Test/Git/외부 Tool 출력

외부 명령은 `text=True`와 OS 기본 locale에 의존하지 않는다.

```text
외부 Process
→ stdout/stderr bytes로 수집
→ UTF-8/UTF-16/Windows code page/CP949/EUC-KR strict 판별
→ 안전하게 읽은 문자열과 사용 인코딩 기록
```

출력을 읽지 못하더라도 다음 실행 사실은 보존한다.

- exit code
- stdout/stderr byte 길이
- raw byte hash
- 실행 모드

즉 Build가 실패했는데 오류문자열 인코딩만 읽지 못한 경우에도 `실패` 자체를 성공으로 바꾸지 않는다.

## 5. CMD/BAT

Windows의 `.cmd`/`.bat` 파일은 `shell=True`에 맡기지 않고 명시적으로 CMD 경계로 실행한다.

```text
COMSPEC /d /s /c <command>
```

다음과 같은 프로젝트 명령을 지원하는 방향이다.

```text
.\mvnw.cmd test
.\scripts\build.cmd
```

한글 경로가 포함되어도 argv와 출력 decoding을 별도로 처리한다.

## 6. PowerShell

`.ps1` 실행 시 사용 가능한 PowerShell Host를 명시적으로 선택한다.

우선순위:

```text
pwsh (PowerShell 7+)
→ powershell.exe (Windows PowerShell)
```

자동 실행 시 기본 옵션:

```text
-NoLogo -NoProfile -NonInteractive -File
```

조직 보안정책을 우회하기 위해 `ExecutionPolicy Bypass`를 Harness가 임의로 추가하지 않는다.

사용자가 이미 `powershell.exe` 또는 `pwsh`를 명시한 명령은 다시 감싸지 않는다.

## 7. Git 한글 파일명

변경 파일 확인에서는 Git의 quoted path에 의존하지 않도록 다음 원칙을 사용한다.

- `core.quotepath=false`
- NUL delimiter 기반 파일 목록

따라서 다음과 같은 파일명도 변경 파일 탐지에서 보존하는 것을 목표로 한다.

```text
src/근태/근무계획Service.java
```

## 8. 문제가 생겼을 때

Agent에게 다음처럼 요청한다.

```text
방금 실행한 빌드 로그의 한글 인코딩 상태를 확인해줘.
```

```text
이 CSV가 CP949인지 확인하고 손실 없이 Intake 가능한지 봐줘.
```

다음 방식은 권장하지 않는다.

- `errors="replace"`로 깨진 글자를 정상 근거로 사용
- 실패한 외부 명령의 exit code를 무시
- CMD/PowerShell 명령을 무조건 `shell=True`로 실행
- 한글 파일명이 깨졌는데 파일 변경이 없다고 판단

## 9. 관련 Runtime

Harness 관리자 참고:

```text
sdlc/scripts/extract_document_evidence.py
sdlc/scripts/process_runner.py
sdlc/design/contracts/br-document-extraction-contract.json
sdlc/design/contracts/process-execution-contract.json
```

일반 프로젝트 참여자는 이 파일을 직접 수정할 필요가 없다.
