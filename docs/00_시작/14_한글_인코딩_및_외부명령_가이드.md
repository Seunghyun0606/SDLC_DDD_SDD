# 한글 인코딩 및 외부 명령 실행 가이드

## 1. 목적

프로젝트 자료와 Build/Test/정적분석/DB 도구 출력에서 한글이 깨지지 않도록 현재 Harness의 처리 기준을 설명한다.

사람이 Python `encoding` 옵션을 매번 맞춰가며 실행하는 것이 기본 사용법은 아니다. Harness가 지원 경계에서 손실 없이 읽고, 안전하게 읽지 못한 내용은 정상 근거로 사용하지 않는다.

## 2. MD/TXT/CSV 입력자료

텍스트 자료는 손실 없는 strict decoding을 사용한다.

기본 순서:

```text
BOM 확인
→ UTF-8 strict
→ CP949 strict
→ EUC-KR strict
→ 안전하게 읽지 못하면 추출 필요로 표시
```

UTF-16 BOM이 있는 TXT도 지원한다.

원칙:

- 깨진 글자를 `�`로 바꿔 정상 자료처럼 사용하지 않는다.
- 실제 사용한 인코딩을 추출 결과에 기록한다.
- 안전하게 읽지 못하면 해당 텍스트를 업무 판단 근거로 사용하지 않는다.

## 3. XLSX/PPTX/DOCX

Office 문서는 OS 기본 텍스트 인코딩으로 직접 읽지 않는다.

```text
XLSX/PPTX/DOCX
→ ZIP 패키지 내부 OOXML bytes
→ XML Parser
```

따라서 일반적인 한글 Office 문서는 Windows console code page와 분리해서 처리한다.

## 4. Build/Test/Git/외부 Tool 출력

외부 명령 출력은 `text=True`와 OS 기본 locale에만 의존하지 않는다.

```text
외부 Process
→ stdout/stderr bytes 수집
→ UTF-8/UTF-16/Windows code page/CP949/EUC-KR strict 판별
→ 안전하게 읽은 문자열과 사용 인코딩 기록
```

출력을 읽지 못해도 다음 실행 사실은 보존한다.

- exit code
- stdout/stderr byte 길이
- raw byte hash
- 실행 모드

따라서 Build가 실패했는데 오류문자열 인코딩만 읽지 못한 경우에도 실패 자체를 성공으로 바꾸지 않는다.

## 5. CMD/BAT

Windows `.cmd`/`.bat` 파일은 현재 지원한다. `shell=True`에 맡기지 않고 명시적인 CMD 경계로 실행한다.

```text
COMSPEC /d /s /c <command>
```

예:

```text
.\mvnw.cmd test
.\scripts\build.cmd
```

한글 경로가 포함되어도 명령 인자와 출력 decoding을 별도로 처리한다.

사용자가 `cmd.exe`를 직접 명시한 명령은 중복해서 다시 감싸지 않는다.

## 6. PowerShell

`.ps1` 실행도 현재 지원한다. 사용 가능한 PowerShell Host를 명시적으로 선택한다.

Windows 기본 탐색 순서:

```text
pwsh.exe / pwsh
→ powershell.exe / powershell
```

자동 실행 옵션:

```text
-NoLogo -NoProfile -NonInteractive -File
```

Harness는 조직 보안정책을 우회하기 위해 `ExecutionPolicy Bypass`를 임의로 추가하지 않는다.

사용자가 `powershell.exe` 또는 `pwsh`를 직접 명시한 명령은 다시 감싸지 않는다.

## 7. Git 한글 파일명

변경 파일 확인에서는 Git의 quoted path에 의존하지 않는다.

- `core.quotepath=false`
- NUL delimiter 기반 파일 목록

따라서 다음과 같은 한글 파일명도 변경 파일 탐지에서 보존한다.

```text
src/근태/근무계획Service.java
```

## 8. 안전하게 Decode하지 못한 로그

외부 Process 자체의 exit code는 보존하지만, decode에 실패한 stdout/stderr 본문은 정상 진단 텍스트처럼 신뢰하지 않는다.

결과에는 다음 Metadata를 남길 수 있다.

```text
encoding / decode status / byte length / sha256
```

raw bytes 전체를 일반 JSON에 복제하여 보관하는 것이 기본 정책은 아니다.

## 9. 문제가 생겼을 때

Agent에게 다음처럼 요청할 수 있다.

```text
방금 실행한 빌드 로그의 한글 인코딩 상태를 확인해줘.
```

```text
이 CSV가 CP949인지 확인하고 손실 없이 Intake 가능한지 봐줘.
```

다음 방식은 사용하지 않는다.

- `errors="replace"`로 깨진 글자를 정상 근거로 사용
- 실패한 외부 명령의 exit code 무시
- CMD/PowerShell 명령을 무조건 `shell=True`로 실행
- 한글 파일명이 깨졌는데 변경 파일이 없다고 판단
- PowerShell 보안정책을 자동 우회
