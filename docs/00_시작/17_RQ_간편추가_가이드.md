# RQ 간편추가 가이드

## 1. 목적

최초 요구사항 Excel을 Intake한 뒤 프로젝트 진행 중 새 요구사항이 한두 건 추가되는 경우, Excel을 다시 만들거나 전체 Intake를 반복하지 않고 자연어로 새 RQ를 추가하는 방법을 설명한다.

이 기능은 **추가 요구사항 한 건/소수 건을 빠르게 등록하는 용도**다. 최초 요구사항 전체 목록이나 대량 등록은 기존 XLSX Intake를 사용한다.

## 2. 가장 쉬운 사용법

Agent에게 다음처럼 말한다.

```text
새 RQ 추가해줘. 승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

Cursor에서는:

```text
/rq-add 승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

Agent가 요청 원문을 보존하고, 필요하면 원문의 의미를 넓히지 않는 짧은 제목을 만든 뒤 공식 `rq-add` Runtime을 실행한다.

## 3. RQ를 만들 때 어떤 정보를 주면 되는가

### 3.1 최소 정보

가장 기본적으로 다음 두 내용을 사용한다.

```text
요구사항명
요청 내용
```

예:

```text
요구사항명: 승인 전 연차신청 취소
요청 내용: 직원이 승인되기 전에는 연차신청을 직접 취소할 수 있게 해줘.
```

`요청 내용`은 반드시 있어야 한다.

`요구사항명`을 사용자가 따로 적지 않아도 요청 내용이 충분히 명확하면 Agent가 작업목록에서 알아보기 쉬운 짧은 제목을 만들 수 있다. 제목을 만드는 과정에서 조건/예외/정책을 새로 추가하면 안 된다.

### 3.2 있으면 좋은 정보

다음 내용은 있으면 초기 분석이 더 쉬워진다.

```text
현재 문제/배경
기대 결과
적용 범위
외부 요구 ID
```

예:

```text
새 RQ 추가해줘.

요구사항명: 승인 전 연차신청 취소
요청 내용: 직원이 승인되기 전에는 연차신청을 직접 취소할 수 있게 해줘.
현재 문제/배경: 잘못 신청하면 담당자에게 취소를 요청해야 해.
기대 결과: 본인이 직접 취소하고 사용 예정 연차를 다시 사용할 수 있어야 해.
적용 범위: 연차신청
외부 요구 ID: HR-NEW-017
```

이 중 모르는 내용은 비워도 된다. 없는 값을 Agent가 추측해서 채우지 않고 후속 `/work`에서 조사하거나 사람에게 확인한다.

### 3.3 처음부터 넣지 않아도 되는 정보

다음은 RQ 생성 시 사용자에게 요구하지 않는다.

```text
RQ 번호 / Sequence
Java Class / Method
JSP / XML / Query ID
Table / Column
프로그램 ID
담당자 / 일정 / WBS
상세 Business Rule
참고문서 연결표
```

처리 위치:

```text
RQ 번호                → rq-add Runtime
Source/DB/Program 정보  → /work
담당자/일정/WBS         → /rq-list
확정 업무규칙            → /work 또는 사람 확인, 기존 정책 변경이면 /change
참고문서                 → /rq-ref
```

## 4. CLI로 직접 추가

최소 형태:

```bash
python sdlc/scripts/harness.py rq-add \
  --title "근무계획 승인 후 수정 제한" \
  --request "승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘."
```

기초정보까지 같이 넣을 경우:

```bash
python sdlc/scripts/harness.py rq-add \
  --title "승인 전 연차신청 취소" \
  --request "직원이 승인되기 전에는 연차신청을 직접 취소할 수 있게 해줘." \
  --background "잘못 신청하면 담당자에게 취소를 요청해야 한다." \
  --desired-result "본인이 직접 취소하고 사용 예정 연차를 다시 사용할 수 있다." \
  --scope "연차신청" \
  --external-id "HR-NEW-017"
```

간단한 경우에는 원문만 전달할 수도 있다.

```bash
python sdlc/scripts/harness.py rq-add \
  "승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘."
```

## 5. 내부 처리 흐름

```text
새 요구사항 원문
→ 기존 RQ 변경인지 새 RQ인지 확인
→ 입력한 기초정보 정리
→ 기존 중복 후보 확인
→ 현재 기준 정보 파일의 RQ 번호 확인
→ 다음 RQ ID 선택
→ 요청 원문 그대로 보존
→ 새 RQ를 분석 전 상태로 추가
→ 기준 정보 Revision Guard로 저장
→ RQ 작업목록 자동 갱신
→ 새 RQ ID + 아직 확인할 내용 반환
```

새 요구사항을 추가했다고 해서 세부 업무규칙까지 자동 확정되는 것은 아니다.

예를 들어:

```text
승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

라는 요청에 다음 내용이 없다면 Agent가 임의로 채우지 않는다.

```text
- 승인자는 누구인가?
- 관리자는 예외 수정할 수 있는가?
- 승인 취소 후에는 다시 수정할 수 있는가?
- 수정 제한 시점은 언제인가?
```

필요한 내용은 이후 `/work` 조사와 사람 확인을 통해 보완한다.

## 6. Intake / rq-add / change 차이

```text
프로젝트 최초 요구사항 Excel
또는 많은 요구사항을 한 번에 입력
→ intake

프로젝트 진행 중 새 요구사항 한두 건
→ rq-add

기존 RQ의 업무 의미/정책/범위 변경
→ change

담당자/일정/우선순위 등 PM 정보 변경
→ rq-list
```

예:

```text
"새로 모바일에서도 급여명세서를 조회해야 해"
→ rq-add

"RQ-003에서 조회 대상을 재직자에서 퇴직자까지 확대해줘"
→ change
```

## 7. 중복 처리

동일한 요청 원문 또는 동일한 요구사항명이 이미 등록되어 있으면 기본적으로 새 RQ를 만들지 않고 기존 RQ인지 확인하도록 한다.

문장이 비슷하다는 이유만으로 자동 병합하지 않는다.

실제로 별도 요구사항이 맞다고 확인한 경우에만 `--allow-duplicate`를 사용할 수 있다.

외부 요구 ID가 이미 사용 중이면 자동으로 다른 RQ에 덮어쓰거나 병합하지 않는다.

## 8. RQ 번호와 현재 단일 작성자 운영

사용자는 번호를 직접 정할 필요가 없다.

현재:

```text
RQ-001
RQ-002
RQ-003
```

이 있다면 Runtime이 현재 기준 정보 파일을 보고 다음 번호를 선택한다.

```text
RQ-004
```

현재 RQ 번호는 별도 중앙 Sequence Server가 아니라 `sdlc/canonical/store.json`의 현재 `RQ-NNN`을 기준으로 계산한다.

따라서 **현재 프로젝트에서는 RQ 생성 담당자를 한 명으로 운영한다.**

```text
RQ 생성 담당자 1명
→ 현재 번호 확인
→ 새 RQ 생성
→ 저장 완료
→ 다음 RQ 생성
```

여러 사람/Agent가 동시에 RQ를 생성하는 방식은 현재 지원 범위로 보지 않는다.

Canonical 저장 자체에는 Lock/Revision Guard가 있기 때문에 충돌로 파일이 조용히 덮어써지지는 않지만, 두 사람이 동시에 다음 번호를 계산하는 중앙 Sequence 기능은 아직 없다.

충돌이 발생하면 Runtime은 자동으로 다른 번호를 재선점하지 않는다.

```text
RQ_ADD_CONFLICT_RETRY_REQUIRED
→ 앞의 RQ 생성/기준 정보 변경이 끝난 뒤
→ 지정된 RQ 생성 담당자가 다시 실행
```

여러 사람이 동시에 RQ를 생성할 수 있는 중앙 Sequence/Reservation 기능은 Framework Enhancement TODO에 후속 고도화 항목으로 관리한다.

## 9. 추가 후 RQ 작업목록

성공한 RQ는 자동으로 PM 작업목록 갱신을 시도한다.

```text
docs/00_관리/RQ_작업목록.md
sdlc/runtime/management/rq-worklist.json
```

필요하면 직접 다시 갱신할 수 있다.

```bash
python sdlc/scripts/harness.py rq-list refresh
```

PM용 Excel도 다시 Export할 수 있다.

```bash
python sdlc/scripts/harness.py rq-list export \
  --format xlsx \
  --output docs/00_관리/RQ_작업관리.xlsx
```

담당자/일정/WBS 같은 PM 정보는 RQ 생성 Prompt에 억지로 섞지 않고 이 작업목록에서 관리한다.

## 10. 추가하고 바로 분석하고 싶을 때

Agent에게:

```text
새 RQ 추가하고 바로 분석해줘.
승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

라고 요청할 수 있다.

Agent는 먼저 `rq-add` 성공으로 생성된 실제 RQ ID를 받은 뒤 그 ID로 `/work`를 수행한다.

```text
rq-add
→ RQ-014 생성
→ /work RQ-014
```

새 RQ ID를 추측해서 `/work`를 먼저 실행하지 않는다.

## 11. 주의사항

- `sdlc/canonical/store.json`을 사람이 직접 수정하지 않는다.
- 현재는 지정된 한 명의 RQ 생성 담당자만 `rq-add`를 실행한다.
- 새 RQ 추가는 기존 RQ 변경 수단이 아니다.
- 사용자 원문을 보기 좋은 문장으로 바꾼 뒤 원문인 것처럼 저장하지 않는다.
- 제목은 짧게 정리할 수 있지만 원문에 없는 정책을 추가하지 않는다.
- 모르는 배경/기대 결과/범위는 비워두고 후속 분석에서 확인한다.
- RQ 추가만으로 Source 분석이나 개발이 완료된 것은 아니다.
- 대량 요구사항은 기존 XLSX Intake를 사용한다.
