# RQ 간편추가 가이드

이 문서는 최초 요구사항 Excel을 Intake한 뒤 프로젝트 진행 중 **새 요구사항 한두 건을 자연어로 빠르게 추가**하는 방법을 설명한다.

대량 요구사항이나 고객 파일 전체는 `intake`를 사용한다.

## 1. 가장 쉬운 사용법

Agent에게 다음처럼 말한다.

```text
새 RQ 추가해줘. 승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

Cursor:

```text
/rq-add 승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

CLI:

```bash
python sdlc/scripts/harness.py rq-add \
  --title "근무계획 승인 후 수정 제한" \
  --request "승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘."
```

## 2. 최소 입력

필수는 `요청 내용`이다.

```text
요청 내용: 승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

요구사항명을 생략하면 Agent/Runtime이 원문의 의미를 넓히지 않는 짧은 제목을 만들 수 있다.

## 3. 있으면 좋은 정보

```text
요구사항명
현재 문제/배경
기대 결과
적용 범위
외부 요구 ID
```

예:

```text
새 RQ 추가해줘.

요구사항명: 승인 전 연차신청 취소
요청 내용: 직원이 승인되기 전에는 연차신청을 직접 취소할 수 있게 해줘.
현재 문제/배경: 잘못 신청하면 담당자에게 취소를 요청해야 해.
기대 결과: 본인이 직접 취소할 수 있어야 해.
적용 범위: 연차신청
외부 요구 ID: HR-NEW-017
```

모르는 항목은 비워도 된다. 없는 업무정책이나 기술정보를 임의로 채우지 않는다.

## 4. 처음부터 넣지 않아도 되는 정보

다음은 RQ 생성 시 사용자에게 요구하지 않는다.

```text
RQ 번호
Java Class / Method
JSP / XML / Query ID
Table / Column
프로그램 ID
담당자 / 일정 / WBS
상세 업무규칙
참고문서 연결표
```

처리 위치:

```text
RQ 번호               → rq-add Runtime
Source/DB/Program 정보 → /work
담당자/일정/WBS        → rq-list
기존 정책 변경         → /change
참고문서               → rq-ref
```

## 5. CLI 예

원문만 전달:

```bash
python sdlc/scripts/harness.py rq-add \
  "승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘."
```

기초정보 포함:

```bash
python sdlc/scripts/harness.py rq-add \
  --title "승인 전 연차신청 취소" \
  --request "직원이 승인되기 전에는 연차신청을 직접 취소할 수 있게 해줘." \
  --background "잘못 신청하면 담당자에게 취소를 요청해야 한다." \
  --desired-result "본인이 직접 취소할 수 있다." \
  --scope "연차신청" \
  --external-id "HR-NEW-017"
```

## 6. 내부 처리 흐름

```text
새 요구사항 원문
→ 동일 원문으로 만든 기존 RQ 확인
→ 같은 제목의 다른 요청이 있는지 확인
→ 외부 요구 ID 중복 확인
→ 현재 RQ 번호 확인
→ 다음 RQ ID 선택
→ 요청 원문 보존
→ 분석 전 상태로 저장
→ RQ 작업목록 갱신
→ 실제 생성된 RQ ID 반환
```

RQ를 추가했다고 세부 업무규칙이나 Source 영향이 자동 확정되는 것은 아니다.

## 7. 중복 처리 — 현재 정확한 규칙

### 7.1 같은 요청 원문

동일한 요청 원문으로 이미 `rq-add`가 성공했다면 새 RQ를 만들지 않는다.

```text
같은 요청 원문
→ 기존 RQ ID 반환
→ 기준 정보 변경 없음
→ 새 번호 소비하지 않음
```

표시 제목을 나중에 다르게 전달하더라도 동일 원문이면 기존 RQ를 재사용한다.

### 7.2 같은 제목 + 다른 요청 원문

같은 요구사항명이 이미 있는데 요청 원문이 다르면 자동으로 같은 RQ라고 판단하지 않는다.

```text
같은 제목 + 다른 원문
→ 중복 검토 필요
→ 기존 RQ 변경인지 별도 신규 RQ인지 확인
```

별도 신규 RQ가 맞다고 사람이 확인한 경우에만 `--allow-duplicate`를 사용한다.

```bash
python sdlc/scripts/harness.py rq-add \
  --title "근무계획 개선" \
  --request "별도의 신규 요구 원문" \
  --allow-duplicate
```

### 7.3 외부 요구 ID 중복

이미 다른 RQ에 등록된 외부 요구 ID를 조용히 덮어쓰거나 병합하지 않는다. 입력을 수정하거나 기존 RQ 변경인지 확인한다.

## 8. Intake / rq-add / change 차이

```text
최초 요구사항 파일 / 많은 요구사항 추가
→ intake

프로젝트 중 새 요구사항 한두 건
→ rq-add

기존 RQ의 요구/정책/범위 변경
→ /change

담당자/일정/WBS/메모 변경
→ rq-list
```

예:

```text
"모바일에서도 급여명세서를 조회해야 해"
→ rq-add

"RQ-003 조회 대상을 재직자에서 퇴직자까지 확대해줘"
→ /change
```

## 9. RQ 번호와 현재 단일 작성자 정책

사용자가 번호를 직접 정할 필요는 없다.

현재 저장소에 다음이 있다면:

```text
RQ-001
RQ-002
RQ-003
```

다음 번호는 `RQ-004`로 계산한다.

현재 번호 할당은 별도 중앙 Sequence Server가 아니라 `sdlc/canonical/store.json`의 현재 RQ 번호를 기준으로 한다.

따라서 현재 프로젝트 운영에서는 **RQ 생성 담당자를 한 명으로 두는 정책**을 사용한다.

기준 정보 저장 자체에는 충돌 방지가 있지만 여러 Agent가 동시에 다음 번호를 예약하는 중앙 Sequence 기능은 없다.

동시 변경 충돌이 발생하면 자동으로 다른 번호를 재선점하지 않고 다시 실행이 필요하다고 반환한다.

## 10. RQ 작업목록 갱신

성공한 RQ는 작업목록 갱신을 시도한다.

대표 결과:

```text
docs/00_관리/RQ_작업목록.md
sdlc/runtime/management/rq-worklist.json
```

필요하면 다시 갱신한다.

```bash
python sdlc/scripts/harness.py rq-list refresh
```

PM Excel도 다시 Export할 수 있다.

```bash
python sdlc/scripts/harness.py rq-list export \
  --format xlsx \
  --output docs/00_관리/RQ_작업관리.xlsx
```

## 11. 추가 후 바로 분석

Agent에게 다음처럼 요청할 수 있다.

```text
새 RQ 추가하고 바로 분석해줘.
승인 완료된 근무계획은 일반 사용자가 수정할 수 없게 해줘.
```

반드시 `rq-add`가 반환한 실제 RQ ID를 사용해 `/work`를 실행한다.

```text
rq-add
→ RQ-014 반환
→ /work RQ-014
```

새 ID를 추측해서 `/work`를 먼저 실행하지 않는다.

## 12. 주의사항

- `sdlc/canonical/store.json`을 사람이 직접 수정하지 않는다.
- 현재는 지정된 한 명의 RQ 생성 담당자가 `rq-add`를 실행한다.
- 새 RQ 추가는 기존 RQ 변경 수단이 아니다.
- 요청 원문을 임의로 확장해서 저장하지 않는다.
- 모르는 배경/기대결과/범위는 후속 분석에서 확인한다.
- RQ 추가만으로 Source 분석이나 개발이 완료된 것은 아니다.
- 대량 요구사항은 `intake`를 사용한다.
