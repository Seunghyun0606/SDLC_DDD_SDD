# 업무정의서 — HRIS / hunel

> **역할**: 하나의 업무/기능 단위에서 무엇을 왜 바꾸는지, 개발자가 이해해야 할 업무 의미와 검증 기준을 정리합니다.
>
> - JSP/Java/XML, `hunelCommonDS`, SQLResource, ibsheet 같은 구현 방식은 `02_작업지시서`에서 다룹니다.
> - 현재 시스템과 소스에서 확인한 내용은 현행 근거이며, 개선 후 업무정책으로 자동 확정하지 않습니다.
> - 사용자는 이 Template의 빈칸을 직접 채우지 않습니다. Agent가 요구자료와 실제 소스를 먼저 분석해 초안을 만들고, 업무 판단이 필요한 사항만 질문합니다.
> - 수정이 필요하면 절 제목이나 내용을 자연어로 지정합니다. Agent는 문서 안의 숨겨진 Block 식별자를 사용해 정확한 위치를 찾아 반영합니다.
> - 사용자가 바로 답할 수 없는 질문은 `추가 확인이 필요한 사항`에 남겨 다음 설계·개발 경계에서 다시 확인합니다.

## 11. 추가 확인이 필요한 사항

> Agent가 질문했지만 사용자가 즉시 답하기 어려운 업무 결정을 정리합니다. 사용자가 이 표를 직접 관리할 필요는 없습니다. 다시 확인할 시점이 되면 다음 Agent가 신규 질문보다 먼저 확인합니다.

| 확인 필요사항 | 현재 확인 내용 / 제안 | 확인 담당 | 개발 영향 | 다시 확인할 시점 | 상태 |
|---|---|---|---|---|---|
|  |  |  | 개발 전 확인 필요 / 진행 가능·추후 보완 / 주의사항 | 다음 작업 / 상세설계 / 프로그램설계 / 개발 시작 전 / 테스트 전 / 최종 검증 전 | 확인 필요 / 확인중 / 제안 / 보류 / 확정 |
