# 작업지시서 — HRIS / hunel Custom Engineering Projection

> **역할**: 업무정의서의 Functional Intent를 실제 hunel Program Source에 연결하는 Program 단위 구현 명세입니다.
>
> - 업무 의미를 여기서 다시 정의하지 않습니다.
> - 하나의 Unit에 여러 Program ID가 있으면 Program별로 이 문서를 생성할 수 있습니다.
> - hunel 고유 구현 방식(JSP + Java + XML, ibsheet, doAction, 권한 Framework, Procedure 연동)은 이 문서에서 다룹니다.
> - Source Write는 `Source Change Boundary`에 포함된 대상과 승인된 추가 대상에만 허용합니다.
> - **사용자는 이 Template의 표/빈칸을 직접 작성하지 않습니다.** Agent가 Source/Canonical/개발표준을 먼저 분석해 초안을 만들고, 사람 결정이 필요한 항목만 질문합니다.
> - 수정 요청은 기존 Section ID를 Block ID로 사용합니다. 예: `이 문서의 [BLOCK:B-PROC]에서 Procedure 파라미터 영향만 다시 검토해줘`, `이 문서의 [BLOCK:D.1] Source Change Boundary에 XML 파일을 추가해줘`.

# D. Source Change Boundary / Readiness

## D.1 Source Change Boundary
| Change | Artifact / Object | 변경유형 | 목적 | 실행 책임 | 허용 방식 |
|---|---|---|---|---|---|
|  | JSP | ADD/MOD/DEL/VERIFY |  | DIRECT_MODIFY |  |
|  | Java |  |  | DIRECT_MODIFY |  |
|  | XML |  |  | DIRECT_MODIFY |  |
|  | Procedure/DDL |  |  | SCRIPT_OUTPUT / HUMAN_OPERATION |  |

### 실행 책임
- `DIRECT_MODIFY`: Repository Source를 Agent가 직접 변경 가능
- `SCRIPT_OUTPUT`: Agent가 SQL/배포 Script를 만들고 실제 반영은 사람이 수행
- `HUMAN_OPERATION`: 관리화면/DB/외부시스템에서 사람이 실행
- `VERIFY_ONLY`: 변경 없이 영향/회귀 검증만 수행

## D.2 Open / Execution Guard
| Open | 분류 | 제한 Source/Action | 해소 조건 | 상태 |
|---|---|---|---|---|
|  | SOURCE_BLOCK / ITERATE / ALERT |  |  | OPEN / CLOSED |

### SOURCE_BLOCK 예시
- Program ID / 실제 Source 대상이 불확실
- 핵심 Rule/상태전이/권한 정책이 미확정
- Table/Procedure 변경 대상 또는 Parameter가 미확정
- 기존 Source 영향 범위가 불충분해 잘못된 파일 Write 가능성이 큼

### ITERATE 예시
- 대상/업무 동작은 확정됐고 Column 폭, 정렬, UI 문구처럼 구현 후 조정 가능한 세부사항
