# v1.6.0-rc.1 Complexity Reduction / Executable Core

## 목적
v1.5.9까지 추가된 기능을 더 확장하기 전에 실제 프로젝트 사용성을 기준으로 문서·상태·설정 복잡도를 줄인다.

핵심 원칙은 다음과 같다.

1. 같은 업무정보는 한 번만 작성한다.
2. 사람에게 필요한 정보와 Machine metadata를 분리한다.
3. Functional Design은 업무/기능 의미의 기준 문서다.
4. Program Spec은 Functional Design을 반복하지 않고 실제 구현 Target과 구현 차이만 추가한다.
5. OPEN은 사람에게는 간단한 진행 상태로 표시하고 세부 분류/근거 코드는 Machine metadata로 유지한다.
6. /setup은 최소 5개 입력으로 시작 가능해야 하며 나머지 Profile은 필요할 때만 고급 설정으로 확장한다.
7. 기존 RQ/FR/BR/PGM/TASK/AC/TC 및 Evidence 안전 규칙은 유지한다.
8. Brownfield Framework 분석은 Core에 흡수하지 않고 Project Adapter 경계를 유지한다.
9. Source Drift는 Reverse Engineering 전체가 아니라 Drift/Reverse Review Candidate 기능으로 표현한다.
10. 새 Template/Contract 추가보다 기존 구조 축소를 우선한다.

## 이번 RC 범위

### 1. Functional Design / Program Spec 책임 분리
Functional Design이 다음의 의미상 Source of Truth를 가진다.
- 6하원칙 업무 시나리오
- AS-IS / TO-BE
- 화면/사용자 동선
- Field 의미와 Validation
- CRUD 의미
- Business Rule / 상태 / 예외
- 논리 Data 요구
- Integration 요구
- Authorization / NFR
- AC 연결

Program Spec은 다음만 추가한다.
- Functional Design 참조 및 적용 범위
- 실제 PGM/Entry Point/Source Symbol
- Field→DTO/API/DB Mapping 차이
- 실제 Query/Table/Column/Mapper
- Transaction/Concurrency/Idempotency
- Integration 구현 Contract
- Error/Security/Observability 구현 방식
- TASK/AC/TC와 실제 Source 변경 대상
- 구현 준비도와 남은 OPEN

Program Spec에서 Functional Design 내용을 다시 풀어 쓰지 않는다.

### 2. OPEN 사람 표시 단순화
Machine 상태는 기존 호환성을 위해 유지한다.

사람 표시 상태는 다음 5개로 축소한다.
- 미확정
- 확인중
- 제안
- 확정
- 보류

`decision_domain`, `resolution_method`, `basis_class`, 내부 status code는 기본 사용자 문서에서 직접 입력시키지 않는다. Agent/Script가 가능한 범위에서 계산하고 필요 시 내부 부록에서만 표시한다.

### 3. /setup Fast Path
최초 시작 시 다음만 묻는다.
1. 프로젝트 유형: Greenfield / Brownfield / Hybrid / Auto
2. 요구사항 또는 변경요청 위치
3. Source/Repository 위치(없으면 없음)
4. Build/Test 경로(모르면 자동탐색)
5. 고객용 문서 필요 여부

용어, Authority, Customer Section, BR Intake, Impact Adapter 등은 기본값으로 시작하고 실제 필요가 확인될 때 Advanced Setup에서 변경한다.

## 유지하는 Core
- Human Truth / Existing System Evidence / Proposed Design 분리
- RQ → FR/Scenario → BR → PGM → TASK → AC/TC → Source 추적
- OPEN/가정/충돌을 발명하지 않는 규칙
- Brownfield Project Adapter 경계
- Source Hash 및 Drift 안전장치
- Business Truth 자동 역갱신 금지

## 제거/축소 방향
- 동일한 6W/Field/CRUD/Rule을 Functional Design과 Program Spec에 중복 작성하지 않는다.
- OPEN Workbook에서 10개 이상 Machine column을 사람이 직접 관리하지 않는다.
- /setup 최초 진입에서 모든 Profile을 필수 설정으로 취급하지 않는다.
- 고객용 문서는 내부 Machine state를 노출하지 않는다.

## 후속 RC
이번 RC는 복잡도 축소의 첫 묶음이다. 다음 RC에서 별도 검증한다.
- Requirement + Requirement Analysis 통합
- Interview View와 OPEN Workbook 파생 관계 단순화
- 고객문서 8종 통합 여부
- Stage 실행 경로의 실제 Canonical Delta executor
- 저수준 Agent 반복 실행 기반 behavioral validation

## 비호환성 정책
기존 Machine key와 상태값은 당분간 유지한다. 사용자 View와 작성 UX부터 단순화하고, 실제 사용 데이터의 migration 계획이 확인된 뒤 내부 schema 제거를 검토한다.
