> Branch: `SDLC_DESIGN_SESSION_SECOND/p0.7/provider-adapter-conformance-v1`

## 1. Verdict

**P0.7 REFERENCE ADAPTER / CONFORMANCE HARNESS: IMPLEMENTED WITH RUNTIME EXECUTION EVIDENCE OPEN**

구현 범위는 완료했다.

- Stack-neutral Local Filesystem Source Adapter
- Stack-neutral Subprocess Test Adapter
- Dynamic Adapter Conformance Runner
- generic source/test fixture

그러나 세션 실행환경에서 GitHub DNS가 해석되지 않아 해당 Branch를 별도 checkout하여 Repository self-test를 실제 실행하지 못했다.

따라서 다음은 주장하지 않는다.

- Repository checkout 기반 conformance PASS
- CI PASS
- 실제 고객 Adapter PASS
- Production Provider Ready

## 2. Core 구조

```text
P0.6 Provider Request
→ Adapter describe()/invoke()
→ Tool / Local Runtime
→ P0.6 Provider Response
→ P0.7 Conformance Runner
→ P0.6 Request/Response Validator
→ Conformance Result
```

Adapter가 교체되어도 Stage Input Pack, Command Router, Provider Envelope는 바꾸지 않는다.

## 3. Reference Source Adapter

Module:

`sdlc.adapters.reference.local_filesystem_source`

지원 Capability:

- `source.snapshot.read`
- `source.object.read`
- `source.search`
- `source.diff`

특징:

- read only
- language/framework/database neutral
- SHA-256 revision/evidence
- bounded file count/byte scan
- relative path root escape 차단
- Source Evidence `OBSERVED`
- bounded limit 도달 시 `PARTIAL`
- unsupported operation은 `BLOCKED`

파일시스템 자체가 Business Truth를 생성하지 않는다.

## 4. Reference Test Adapter

Module:

`sdlc.adapters.reference.subprocess_test`

지원 Capability:

- `test.discover`
- `test.execute`
- `test.result.read`

특징:

- `shell=False`
- command는 argv list만 허용
- timeout 상한
- stdout/stderr 제한
- discovery pattern은 Project/Adapter config가 주입
- 특정 test framework naming convention을 Core Adapter가 가정하지 않음

### Provider 상태와 Test Outcome 분리

```text
process exit 0
→ Provider OK
→ test_status PASSED

process exit non-zero
→ Provider OK
→ test_status FAILED

timeout
→ Provider BLOCKED
→ ADAPTER_TIMEOUT
→ retryable true

command not found
→ Provider BLOCKED
→ TEST_COMMAND_NOT_FOUND
```

Test failure를 Provider 장애로 오인하지 않는다.

## 5. Conformance Runner

Script:

`sdlc/scripts/run_provider_conformance.py`

Adapter module을 동적으로 로드한다.

필수 Protocol:

- `describe()`
- `invoke(request, config)`

Runner는 Adapter descriptor에서 임시 Registry를 구성하고 P0.6 Validator를 재사용한다.

검증:

- descriptor 필수값
- provider type/state/mode/capability
- request schema
- request/response correlation
- response status
- evidence truth/locator/revision
- expected result assertion

미지원 Capability Case는 Router 경로와 별개로 Adapter 자체가 안전하게 `BLOCKED`하는지 직접 확인한다.

## 6. Generic Source Conformance

업무 의미가 없는 다음 fixture만 사용한다.

Before:

```text
format_message
calculate_total
```

After:

```text
format_message 변경
calculate_total 변경
```

Cases:

1. Snapshot OK
2. Object Read OK
3. Text Search OK
4. Before/After Diff OK
5. Path traversal BLOCKED
6. Unsupported capability BLOCKED
7. bounded scan → PARTIAL (self-test)

Pilot Requirement/Table/Symbol은 사용하지 않는다.

## 12. 실행 검증 상태

따라서 Repository 파일을 현재 실행환경으로 가져와 다음 명령을 실제 실행한 Evidence는 없다.

`conformance-case-matrix.yaml`에는 이를 명시적으로:

- `repository_checkout_executed: false`

로 기록했다.

## 13. P0.6에서 발견된 문서 정합성 개선

기존 Provider Runtime 가이드의 체크리스트에 닫힌 Core Provider Enum을 전제하는 문구가 남아 있었다.

P0.6 확장모델과 맞게 다음으로 수정했다.

- Provider Type은 확장 가능한 대문자 식별자
- Router는 Type switch가 아니라 Capability exact match

따라서 Deployment/Monitoring/Notification 등 신규 Adapter를 추가할 때 Core Router 수정이 필요 없다는 원칙과 문서를 일치시켰다.
