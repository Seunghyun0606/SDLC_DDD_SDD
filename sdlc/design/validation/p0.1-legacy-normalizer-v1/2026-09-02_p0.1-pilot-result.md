## 4. Deterministic Guards

### Legacy Normalizer

다음은 실패한다.

- 중복 `source_requirement_id`
- Level2/요구사항명 누락
- Exact Group 안에 다른 key의 Row 혼입
- Source Row가 여러 exact group에 중복 소속
- `ALL_ROWS_EXACTLY_ONCE`인데 Row 누락
- `publish_canonical=true`
- Group 단계에서 Canonical Decision 확정

### Group Boundary

다음은 실패한다.

- 여러 Source Row인데 `scope_type=ROW`
- Group Boundary인데 `source_group_id` 누락
- `source_count` 불일치
- 동일 Source ID가 복수 Boundary Record에 중복
- `UNRESOLVED`인데 Canonical RQ/FR ID 발행

### Stage Input Pack

다음은 실패한다.

- 2개 이상 Source ID인데 `granularity=ROW`
- GROUP/SUBGROUP인데 `source_group_id` 누락
- Source Requirement ID 중복
- `BOUNDARY_AMBIGUOUS`인데 Confirmed Target 발행

## 5. Low-Agent 평가 변화

### 개선된 부분

- Source Row 보존은 완전 기계 처리 가능
- Exact Grouping은 L1 Agent 없이도 Script 실행 가능
- Group ID가 deterministic해 Agent 교체 시 ID drift가 감소
- Group Pack으로 handoff 수가 Row 수에 비례해 증가하지 않음
- RQ Boundary가 모호할 때 Canonical 발행을 Validator가 막음

### 여전히 L2/Human이 필요한 부분

- Group Candidate가 실제 하나의 Business Outcome인지 판단
- 39건을 일마감/월마감/전자결재/선택적근로마감 등으로 Canonical Split할지 판단
- Owner/Release/AC Boundary 결정
- 업무 State/권한/승인·반려·취소 Rule 확정

따라서 Low-Agent 판정은 다음과 같다.

- INTAKE/NORMALIZE: `YES WITH DETERMINISTIC GUARDS`
- GROUP HANDOFF: `YES WITH DETERMINISTIC GUARDS`
- RQ BOUNDARY CONFIRMATION: `L2_OR_HUMAN`
- SOURCE DISCOVERY 이후: Source 입력 부재로 미검증
