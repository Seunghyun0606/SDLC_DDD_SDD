## 1. Verdict

**P0.2 REVIEW/PUBLISH-READY: PASS WITH HUMAN DECISION GATE**

P0.1에서 생성된 Candidate Group을 사용자가 검토할 수 있는 Worklist/Review View로 투영하고, Human/L2가 `CONFIRMED`하기 전에는 Canonical RQ/FR Publish를 막는 계약과 Validator를 구현했다.

실제 첨부 요구사항의 근태마감 39건은 여전히 `OPEN / UNRESOLVED`이므로 Canonical Publish를 수행하지 않았다. 이는 실패가 아니라 입력 Evidence에 맞는 정상적인 Fail-safe 결과다.

## 3. Human/L2 Decision Gate

지원 결정:

- KEEP_AS_RQ
- MAP_TO_EXISTING_RQ_AS_FR
- MERGE_INTO_NEW_RQ
- SPLIT_TO_MULTIPLE_RQ
- REJECT_AS_REQUIREMENT
- UNRESOLVED

`CONFIRMED` 결정은 다음 필드를 모두 요구한다.

- decided_by
- decided_at
- decision_basis
- evidence_ids
- decision_revision >= 1

`OPEN / PROVISIONAL / UNRESOLVED`는 Publish 대상이 아니다.

## 4. Publish Guard

Canonical Publish Request는 다음 조건에서만 생성 가능하다.

```text
CONFIRMED Review Decision
+ Source revision match
+ Source coverage preserved
+ Evidence
+ Decision revision
+ Preallocated Canonical IDs
→ Publish Request
→ Validator
→ PUBLISH_READY
```

Candidate Group ID는 Canonical ID로 재사용할 수 없다.

P0.2에서 Canonical ID allocator를 새로 만들지 않았다. ID allocator가 없으면 임의 ID 생성을 하지 않고 중단한다.

## 7. Physical Canonical Registry 확인

현재 Branch의 Repository tree를 확인했으나 물리 Canonical Entity/Relation Registry 또는 Canonical ID allocator 구현 경로는 발견되지 않았다.

따라서 P0.2에서 임의의 Registry 저장형식을 새로 정의하여 실제 Canonical Write를 수행하지 않았다.

**P0.2의 안전한 종료점은 `PUBLISH_READY`다.**

물리 Registry Write는 별도 Architecture Decision 후 연결해야 한다.
