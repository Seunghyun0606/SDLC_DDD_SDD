## Canonical Runtime
`sdlc/scripts/apply_canonical_delta.py`를 추가하고 `/work`, `/change`에서 실제 실행 경로로 사용한다. 별도 Canonical Contract는 추가하지 않았다.

지원:
- `UPSERT_ENTITY`
- `UPSERT_RELATION`
- `ADD_PROVENANCE`

안전성:
- optimistic `base_revision`
- 동일 `delta_id` idempotent
- all-or-nothing
- Relation endpoint/Entity type 충돌 fail-closed
- `CONFIRMED_BUSINESS`는 `CONFIRMED` Evidence 필요
- Source-derived Evidence가 Confirmed Business 필드 또는 상태를 낮추는 것 차단
- 현행 Source 근거만 추가할 때 `ADD_PROVENANCE` 사용 가능
- DELETE 미지원

Canonical Runtime 15개 행동 테스트가 CI에서 통과했다.

## 저수준 Agent 실행 검증 경계
기존 `agent-execution-contract.json`을 확장해 Stage Result Envelope를 추가했다. 새 Contract는 만들지 않았다.

필수값:
- `stage`
- `artifact_path`
- `canonical_delta`
- `quality_gate`
- `alerts`
- `uncertainty`

`sdlc/scripts/validate_agent_stage_result.py`가 다음을 검증한다.
- Artifact 실제 존재/Repository 상대경로
- path traversal 차단
- unresolved `{{placeholder}}` 차단
- Result Stage와 Delta Stage 일치
- Artifact 경로와 Delta `source_artifact` 일치
- Canonical Delta 자체 유효성
- 현재 Store에서 APPLIED/IDEMPOTENT 가능 여부
- quality FAIL은 non-executable
- uncertainty 상태

`/work`와 `/change`는 `Stage Artifact → Stage Result Envelope → Validator → Canonical dry-run/apply` 순서를 사용한다.

### 반복 실행 비교
Validator는 Stage Result 두 개의 semantic fingerprint를 비교한다. `generated_at / updated_at / created_at / checked_at / observed_at` 같은 volatile field는 제외한다.

중요: 이 기능은 **LLM 자체가 결정론적임을 증명하지 않는다.** 실제 Agent 실행 결과를 같은 기준으로 비교하고 의미 차이를 숨기지 않는 Post-Agent validation이다. 따라서 `LLM_AGENT_GENERATION_REPEATABILITY`는 아직 PENDING이다.
