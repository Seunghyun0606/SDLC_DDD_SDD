## 이번 변경에서 직접 확인한 사항

### 1. Requirement / Requirement Analysis 활성 산출물 통합
- 신규 DECOMPOSE Stage의 Template을 `requirement.md`로 변경했다.
- `requirement.md`가 원문/External ID/목표/Scope/FR/BR 후보/AC/OPEN을 한 문서에서 관리한다.
- `requirement-analysis.md`는 `DEPRECATED_COMPATIBILITY_VIEW`로 전환했다.
- Legacy View에는 FR/BR/AC를 재작성하지 않고 기준 `requirement.md`를 참조하도록 했다.

### 2. Functional Design / Program Spec 책임 분리
- `developer-spec-contract.json`에서 Functional Design을 `SEMANTIC_SOURCE_OF_TRUTH`로 정의했다.
- Program Spec은 `IMPLEMENTATION_DELTA_AND_EXECUTION_READINESS`로 정의했다.
- Program Spec에서 기존의 6W 전체표, 화면 상세, Field 의미 상세, CRUD 의미 상세, 업무규칙 전체 재작성 Section을 제거했다.
- Program Spec은 기능 설계 기준점, 실제 구현 Target, 구현 Mapping/Delta, Query/Table/Source, Transaction, Integration 기술계약, Technical Control, TASK/AC/TC/Source, Readiness 중심으로 축소했다.

### 3. Program DoR 표현 축소
- 기존 17개 의미를 제거하지 않았다.
- 17개 별도 Section 요구를 제거하고 `### 구현 준비도` 한 개 표의 17개 행으로 바꿨다.
- `program-spec-readiness.json`과 `validate_program_spec.py`도 새 표현 방식에 맞췄다.

### 4. OPEN 사용자 UX 축소
- 기존 Machine status/category/domain/method/basis는 호환성을 위해 유지한다.
- 사람에게 보이는 상태는 `미확정 / 확인중 / 제안 / 확정 / 보류` 5개로 제한했다.
- `Decision Domain`, `Resolution Method`, `Basis Class`, 내부 status, downstream impact는 일반 사용자의 필수 입력에서 제외하고 Machine metadata로 이동했다.
- OPEN Workbook의 기본 표를 확인내용/확인방법/현재값·제안/담당/진행상태 중심으로 축소했다.

### 5. /setup 진입 축소
최초 입력을 다음 5개로 정의했다.
1. 프로젝트 유형
2. 요구사항/변경요청 위치
3. Source/Repository 위치
4. Build/Test 경로
5. 고객용 문서 필요 여부

나머지 Profile은 실제 필요 시 Advanced Setup에서 연다.

### 6. 고객문서 8종 → 3개 활성 View
- `customer-document-contract.json`의 활성 문서 유형을 `solution_agreement`, `delivery_scope`, `acceptance_handover` 3개로 제한했다.
- 3개 View가 INTAKE부터 KNOWLEDGE_PROMOTION까지 전체 Workflow Stage를 덮도록 매핑했다.
- 기존 8개 customer document type ID는 삭제하지 않고 `legacy_document_aliases`로 3개 활성 View에 연결했다.
- 신규 Template 3개를 추가했다.
  - `A01_요구_업무_기능_합의서.md`
  - `A02_영향_개발범위_공유서.md`
  - `A03_테스트_인수_운영_결과서.md`
- 기존 8개 Template 파일은 호환 자산으로 유지하며 신규 `/work`에서 별도 8종을 중복 생성하지 않는다.

### 7. 내부 Artifact → Customer View Projection Runtime
기존 `render_customer_document.py`는 Heading과 placeholder만 생성했다. 현재 구현은 다음을 입력으로 받는다.
- 내부 Markdown Artifact
- Canonical JSON Bundle
- 위 파일이 있는 Directory

Contract에 `projection_sections`, `base_section_sources`, `catalog_section_sources`를 추가했고 Renderer가 해당 Mapping을 실행한다.

고객 본문 기본 처리:
- 내부 RQ/FR/BR/PGM/TASK/AC/TC ID 숨김
- Source Hash/Locator/Confidence 숨김
- 내부 상태 코드의 고객용 한국어 표시 변환
- 최신 관련 Stage 우선
- 동일 내용 중복 제거
- 근거가 없는 Section은 추정하지 않고 명시적 미확인 문구 출력

### 8. Reverse 기능 과대표현 방지
Harness capability 명칭을 `SOURCE_DRIFT_AND_REVERSE_REVIEW_CANDIDATE`로 명시했다.
전체 Reverse Engineering, Program Spec 자동 재생성, Business Truth 자동 역갱신은 구현된 것으로 간주하지 않는다.
