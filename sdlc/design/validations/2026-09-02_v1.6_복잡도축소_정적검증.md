### 실제 저장소가 드러낸 Parser 결함
첫 실행에서 두 문제가 발견됐다.
1. Spring Controller 파라미터 내부 `@RequestParam(...)`의 중첩 괄호 때문에 기존 Method regex가 중간에서 끊겼다.
2. Java interface와 MyBatis namespace 이름이 같으면 Java class 후보를 먼저 선택한 뒤 Mapper fallback을 놓쳤다.

기대 검증을 약화하지 않고 Adapter를 수정했다.
- Parameter list balanced-parenthesis scanner 도입
- body balanced scanner 유지
- Java source symbol target이 실제로 없으면 MyBatis namespace/statement로 fallback

## 현재 판정

- 분석가/설계자/개발자/고객을 포함한 사람 대상 사용성 평가
- 필요 시 고객 고유 Production Repository에서 Adapter 정확도/Gap 재검증

이 세 항목은 현재 코드가 자동으로 대체하거나 꾸며낼 수 없는 외부 실증이므로 PASS로 표시하지 않는다.
