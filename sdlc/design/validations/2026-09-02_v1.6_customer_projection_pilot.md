## Pilot에서 발견한 호환 Gap
기존 Pilot 문서는 현재 Template과 달리 frontmatter의 `stage:`가 없고 파일명 `07_DESIGN_...`처럼 Stage를 표현했다.

또한 과거 문서는 `## 30초 요약`, `## 입력/Evidence`, `## 본문`, `## 미확정/Alert/Assumption`, `## 관련 ID/Traceability`를 사용한다.

기존 Projection Runtime이 이 문서들을 디렉터리로 읽으면 Stage가 없는 문서를 모든 고객 View에 포함시킬 위험이 있었다.

## 보완
### Stage 추론
Renderer가 다음 우선순위로 Stage를 판별한다.
1. frontmatter `stage:`
2. 기존 파일명/제목의 Workflow Stage token
3. `KNOWLEDGE`는 현재 `KNOWLEDGE_PROMOTION`으로 alias

Stage를 판별하지 못한 문서는 기본 Profile에서 고객 Projection 대상에서 제외한다.

따라서 00 인덱스, 13 CHANGE, 14 CHECK가 3개 고객 View에 섞이지 않는다.

### Legacy Heading 호환
다음 과거 Heading을 현재 의미로 인식한다.
- `30초 요약` → `한눈에 보기`
- `입력/Evidence` → `입력 및 근거`
- `미확정/Alert/Assumption` → `미확정 사항·주의·가정`
- `관련 ID/Traceability` → `관련 ID 및 추적성`

### 단일 본문 fallback
구형 문서가 세분화 Section 대신 `## 본문`만 가지는 경우, Contract가 Stage별로 지정한 고객 Section에만 본문을 fallback한다.

같은 본문을 여러 고객 Section에 임의 복제하지 않는다.

## 고객 표시 안전성 검증
기존 Pilot Projection에서 다음을 확인했다.
- 실제 요구 내용인 `탄력근로제 개선 최초근무계획 자동 설정하는 기능`은 고객 View에 유지된다.
- `RQ-CAND-0001`, `REQ_TM_FL001`, `PGM-PILOT-001`, `TASK-PILOT-*`, `INT-PILOT-*`, `ASM-PILOT-*` 같은 내부 추적 ID는 기본 고객 본문에서 숨겨진다.
- `Source Hash`, `sha256:` 값은 숨겨진다.
- `SIMULATED_SOURCE_FIXTURE`는 실제 Source처럼 표현하지 않고 고객 친화적 표현으로 변환한다.
- `PILOT_STRUCTURAL_PASS`는 `구조 검증 완료`로 표현한다.
- `REAL_SOURCE_PENDING`은 `실제 시스템 검증 필요`로 표현한다.
- `NOT_RUN`은 `미실행`으로 표현한다.
- Projection 결과에 unresolved `{{placeholder}}`가 남지 않는다.

## 이 Pilot이 증명하는 것
- 기존 문서 체계와 새 3개 Customer View 사이의 하위호환 Projection 경로가 실행된다.
- 디렉터리 입력에서 Stage 경계를 적용할 수 있다.
- 기존 산출물 형식이 새 Template 형식과 달라도 제한된 Legacy Adapter 규칙으로 사용할 수 있다.
- 고객 본문에서 내부 추적/Source 관리 정보를 기본적으로 제거할 수 있다.
- Source가 모의 데이터라는 기존 Evidence 경계를 고객 문서에서 실제 운영 Source처럼 과장하지 않는다.

## 이 Pilot이 증명하지 않는 것
- 실제 Brownfield Repository의 Caller/Callee/Query/Table lineage
- Java/Spring/MyBatis Impact Adapter의 정확성
- 실제 업무 담당자의 고객문서 가독성/합의 효율
- 저수준 LLM Agent가 동일 입력에서 반복적으로 같은 설계 판단을 내리는지
- Canonical Delta executor가 Stage 변경을 자동 반영하는지
- Source 변경에서 Program Spec/Functional Design을 semantic reverse regeneration 하는지
