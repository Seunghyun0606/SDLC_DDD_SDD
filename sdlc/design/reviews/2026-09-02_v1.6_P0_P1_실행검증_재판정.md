## 5. 현재 실행 가능한 최초 도입 경로

### Greenfield

```bash
python sdlc/scripts/harness.py setup \
  --name <project-name> \
  --mode GREENFIELD \
  --delivery STANDARD

python sdlc/scripts/harness.py check --setup
python sdlc/scripts/harness.py work --target <RQ-ID> --plan-only
```

Source가 없거나 기술스택이 미정인 것은 시작 실패로 보지 않는다. Business Truth는 추측 확정하지 않고 OPEN/Proposal로 분리한다.

### Brownfield

```bash
python sdlc/scripts/harness.py setup \
  --name <project-name> \
  --mode BROWNFIELD \
  --delivery STANDARD

python sdlc/scripts/harness.py check --setup
```

`/setup` 결과에서 source/build/test와 Adapter coverage를 확인한 뒤 `/work` 또는 Brownfield Adapter를 사용한다. 찾지 못한 관계는 영향 없음으로 승격하지 않는다.

## 6. Production Ready 전에 남은 필수 실증

다음은 CI 성공으로 대체할 수 없다.

1. **실제 EXTERNAL_AGENT Provider E2E**
   - Greenfield 한 줄 요구 → DECOMPOSE/DESIGN/PROGRAM
   - Brownfield 변경 요청 → Source evidence → impact → program → development/test
   - 최소 3회 반복 실행 semantic repeatability 측정
2. **비숙련 사용자 First-use Pilot**
   - 업무 분석가/설계자/개발자가 README만 보고 setup과 첫 work를 수행
   - Harness 설계자 개입 횟수와 소요 단계 기록
3. **Hosting-level Git Guard**
   - default branch protection/ruleset 활성화
   - required CI check 지정
4. **Git commit consistency 검증**
   - 성공한 Source+Canonical+Artifact가 동일 변경 단위로 commit/PR 되는 운영 규칙 검증
5. 프로젝트가 요구할 경우 scanned PDF/OCR, live DB/APM/Broker/API Catalog를 실제 Tool/MCP로 연결
6. 고객 proprietary Brownfield Repository가 제공될 경우 Public pilot과 별도로 실제 coverage 측정
