# 프로그램 상세설계

> 이 문서는 기능/업무 상세설계를 실제 프로그램과 소스 변경으로 연결하는 개발자용 구현 명세입니다. 업무 의미를 여기서 다시 만들지 않고, 실제 구현에 필요한 기술 정보와 변경 범위에 집중합니다.
>
> 모든 기술 항목을 항상 작성하지 않습니다. **실제 변경 특성에 해당하는 구현 영역만 활성화**하고 나머지는 최종 문서에서 제거합니다.
>
> 사용자는 이 Template의 빈칸을 직접 채우지 않습니다. Agent가 관련 소스와 개발표준을 먼저 분석해 초안을 만들고, 사람 결정이 필요한 항목만 질문합니다. 수정이 필요하면 절 제목이나 대상 내용을 자연어로 지정하면 됩니다.

## 5. 필요한 구현 영역

> 아래 목록은 적용 여부를 판단하기 위한 표준 분류입니다. 해당되지 않는 영역은 최종 문서에서 제거할 수 있으며, 프로젝트 Custom Template은 기술스택 고유 영역을 추가할 수 있습니다.

| 구현 영역 | 적용 조건 / 근거 | 설계해야 할 핵심 | 적용 여부 |
|---|---|---|---|
| UI / 사용자 동작 | 화면·사용자 동작 변경 | 입력/출력, Action, 상태, Validation | 적용 / 비적용 |
| 데이터 매핑 | DTO/Form/Field 매핑 변경 | 필드 연결, Format, Validation | 적용 / 비적용 |
| 데이터 접근 / Schema | Query/Table/Column 영향 | CRUD, Join, Filter, Schema/Migration | 적용 / 비적용 |
| Transaction / 동시성 | 실행 경계·중복 위험 | Commit/Rollback, Lock, Idempotency | 적용 / 비적용 |
| Interface / Event | 외부 연계 영향 | Contract, Timeout, Retry, 실패 처리 | 적용 / 비적용 |
| Batch / Scheduler | 비동기·정기 실행 | 주기, 재실행, 중복 방지, 운영 통제 | 적용 / 비적용 |
| Security / Authorization | 권한·민감정보 영향 | 인증/인가, Data Scope, Masking/Audit | 적용 / 비적용 |
| DB Procedure / Function | Procedure/Function/Trigger 영향 | 호출 계약, 내부 변경 경계, 배포 책임 | 적용 / 비적용 |
| 성능 / Migration / 운영 | 성능·운영·배포 영향 | SLA, Migration, Rollback, 관측 | 적용 / 비적용 |
| Architecture / 표준 예외 | 구조/표준 영향 | 적용 표준, 예외 이유, 승인/대안 | 적용 / 비적용 |

## 6. 소스 변경 범위

> Agent와 개발자는 아래 목록에 포함된 대상 또는 추가로 확인된 승인 대상 안에서 변경합니다.

| 소스 / 대상 | 변경 유형 | 변경 목적 | 실행 주체 | 적용 방식 | 확인 근거 |
|---|---|---|---|---|---|
|  | 추가 / 수정 / 삭제 / 확인 |  |  | 직접 수정 / 스크립트 산출 / 사람 수행 / 확인만 |  |

### 적용 방식 의미
- **직접 수정**: Repository의 소스를 직접 변경합니다.
- **스크립트 산출**: 적용 스크립트나 산출물을 만들고 실제 반영은 담당자가 수행합니다.
- **사람 수행**: 운영·관리도구·외부시스템에서 담당자가 수행하고 문서에는 절차와 검증 방법을 남깁니다.
- **확인만**: 변경하지 않고 영향과 회귀 여부만 검증합니다.
