# 한글 산출물과 고객 커뮤니케이션 가이드

## 목적
Agent에 익숙하지 않은 설계자·개발자·고객이 같은 SDLC 산출물을 이해할 수 있도록 내부 Canonical과 사용자 표시 문서를 분리한다.

## 1. 내부 Canonical과 사람용 문서를 분리한다
- RQ/FR/BR/PGM/TASK/AC/TC 같은 식별자는 시스템 추적을 위해 유지한다.
- 사람에게 보이는 제목, 표 머리글, 설명, 질문은 한국어 자연어를 기본으로 한다.
- 첫 등장 시 `기능 요구사항(FR)`처럼 한국어 명칭과 코드를 함께 적는다.
- 고객 문서에서는 내부 ID, Source Hash, Confidence를 기본적으로 숨기고 필요할 때 부록으로 표시한다.

## 2. 고객 커뮤니케이션 View
내부 산출물 → Canonical → 고객 문서 View 순서로 생성한다. 고객 문서는 독립적인 Truth Store가 아니다. 고객 회의에서 변경된 내용은 `/change` 또는 `/work`로 다시 Canonical에 반영한다.

### 표준 필수 단락
1. 문서 목적
2. 한눈에 보기
3. 고객과 함께 확인할 내용
4. 합의된 내용
5. 미확정 사항
6. 다음 단계

### 선택 단락
요청 배경, 현재/개선 비교, 업무 영향, 범위/제외범위, 결정 필요사항, 테스트/인수기준, 일정/역할, 위험/대응, 운영 인수, 기술 상세 부록, 근거 상세 부록.

선택 여부는 `customer-document-profile`에서 프로젝트별로 결정한다. 필수 단락은 제거하지 않는다.

## 3. 고객별 용어 변경
`terminology-profile`은 Canonical ID를 바꾸지 않고 표시 용어만 변경한다. 예를 들어 어떤 고객이 '요구사항' 대신 '업무요건', '프로그램' 대신 '개발기능'을 사용해도 내부 RQ/PGM 관계는 그대로 유지한다.
