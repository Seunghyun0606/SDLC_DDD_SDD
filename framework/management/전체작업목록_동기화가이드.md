# Framework 전체작업목록 MD↔Excel 동기화 가이드

이 문서는 **SDLC Framework 자체의 작업목록을 관리하기 위한 도구 가이드**다. 일반 프로젝트 Runtime 배포에는 포함하지 않는다.

## Quick Start

Framework 작업 목록은 Markdown과 Excel 중 편한 View에서 수정할 수 있다. 동기화는 stable `작업ID`, `변경버전`, `최근변경일시`를 사용하며 충돌이 생겨도 다른 업무 진행은 막지 않는다.

```bash
python sdlc/scripts/sync_worklist.py sync --source md
python sdlc/scripts/sync_worklist.py sync --source xlsx
```

단순 변환:

```bash
python sdlc/scripts/sync_worklist.py md-to-xlsx
python sdlc/scripts/sync_worklist.py xlsx-to-md
```

## Source of Truth

- MD/XLSX는 사람이 사용하는 View다.
- `sdlc/canonical/work-items.json`이 동기화 시점의 Canonical 저장소다.
- 컬럼명/순서는 `sdlc/config/worklist-columns.yaml`을 따른다.
- 담당자, 계획일정, 공수는 비어 있어도 정상 처리한다.

## 충돌 처리

같은 `작업ID`를 서로 다른 오래된 revision에서 수정한 경우 값을 자동 덮어쓰지 않는다. 기본 `sync`는 `SYNC_CONFLICT`를 기록하고 다른 Work Item 처리를 계속한다. Framework CI에서 충돌을 실패로 취급하려면 `--strict`를 사용한다.

```bash
python sdlc/scripts/sync_worklist.py sync --source md --strict
```

## Framework 관리 파일

| 파일 | 역할 |
|---|---|
| `docs/00_관리/전체작업목록.md` | 현재 Legacy Framework Markdown View |
| `docs/00_관리/전체작업목록.xlsx` | 현재 Legacy Framework Excel View |
| `sdlc/config/worklist-columns.yaml` | 한글 Header ↔ 내부 key 계약 |
| `sdlc/canonical/work-items.json` | Canonical Work Item 저장소 |
| `sdlc/runtime/sync-conflicts.jsonl` | 동기화 충돌 기록 |
| `sdlc/scripts/sync_worklist.py` | Framework 관리 CLI |

`docs/00_관리/전체작업목록.*`도 장기적으로 `framework/management/`로 옮기는 대상이다. 현재 XLSX binary 보존/이동 경로를 확인할 때까지 원본을 유지한다.
